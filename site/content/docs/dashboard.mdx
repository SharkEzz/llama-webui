The Dashboard shows what `llama-server` is doing right now: how fast it generates, how full its context is, which
requests it served, and how hard the machine works. Keep it open while you chat or send requests from another client.

## Where the numbers come from

llama-webui samples the machine once per polling interval, every 1,000 ms by default, whether a page is open or not.
Each sample reads:

- **`llama-server` itself**: its `/health`, `/slots` and `/metrics` endpoints. llama-webui adds `--metrics` and
  `--slots` to every server it launches, so these are always available for a profile you start from the app.
- **Telemetry**: CPU and memory from `/proc`, GPUs through NVML, `nvidia-smi` or the `amdgpu` driver, and disk
  throughput from the kernel's disk counters. The [System](/docs/system/) page shows the full readings.

Every sample also feeds a history kept in memory for the last 5 minutes by default. Because sampling never stops, the
chart already holds the last few minutes when you open the page. The history is not saved: restarting llama-webui
clears it. You can change the interval and the history length in [Settings](/docs/settings/) (see
[Change the sampling](#change-the-sampling)).

The page title shows the state of the server: **Stopped**, **Starting…**, **Ready**, **Stopping…**, **Crashed**, or
**External** (with its PID) for a server that answers on the configured port but that llama-webui did not launch.

## Tiles

The row of tiles at the top sums up the current activity.

| Tile                       | What it shows                                                                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Generation**             | Tokens generated per second, all busy slots together, measured between the last two samples. It drops to 0 as soon as nothing is generating.                                            |
| **Prompt**                 | Prompt tokens processed per second, measured the same way. Tokens reused from the cache are not processed again, so they do not count.                                                |
| **Speculative acceptance** | Share of drafted tokens the model accepted since the server started. The line below gives the average number of **tokens accepted per draft**. Shown only once the server has drafted. |
| **Context used**           | Tokens held in the context of every slot, as a share of the total context. The line below gives the token counts.                                                                    |

The **Speculative acceptance** tile appears for servers that use a draft model or multi-token prediction (MTP). A
higher acceptance means more tokens per forward pass; see [Speculative decoding and MTP](/docs/guides/speculative-decoding/)
to set it up.

<Callout type="note" title="Instant rate, not request average">

**Generation** and **Prompt** are instant rates over one polling interval: they move during a request and fall back
to 0 between requests. For the average speed of each request, read the [Recent requests](#recent-requests) table.

</Callout>

## System strip

Below the tiles, a strip of gauges shows the load of the machine. It is measured even when no server runs. Click a
gauge to open the [System](/docs/system/) page.

| Gauge                | What it shows                                                                                                                                                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **CPU**              | CPU load of the whole machine.                                                                                                                                        |
| **RAM**              | Memory in use, total minus available, with the amounts in the label (`RAM 7 GiB / 61 GiB`). Page cache that the kernel can free does not count as used.             |
| **VRAM** _card name_ | VRAM in use on each GPU the server runs on, all processes included. Without a running server, every GPU is shown, except hidden and sleeping ones.                    |
| **Model disk**       | Read throughput of the disk that holds the running profile's model, with the disk's name (`Model disk (nvme0n1)`). When that disk is unknown, **Disk** shows the reads of all disks. |

A GPU counts as used by the server once `llama-server` holds more than 64 MiB on it. The model disk is unknown for an
external server and for a model on btrfs, tmpfs or a network filesystem.

If you turn off the **CPU and memory** collector in Settings, the CPU and RAM gauges stay at 0. With the **Disks**
collector off, the disk reading shows `—`.

## Throughput chart

**Throughput (tok/s)** plots the **Generation** and **Prompt** rates over the whole history. Hover over the chart to
read the values at a given time in the legend below it. The vertical scale follows the highest value in view.

## Slots and context

`llama-server` serves requests in slots: each slot holds one conversation's context, and `--parallel` (`-np`) sets how
many there are. The **Slots and context** card lists them.

- Each row shows **Slot** and its number, a **busy** or **free** badge, and the tokens in its context against the
  slot's size, with a bar.
- The tokens in a slot are the whole conversation: the prompt plus everything generated so far. They stay there after
  the request ends, kept for the next one, so a free slot can still show a full context.
- The message **/slots unavailable for this server.** appears when the server does not answer on `/slots`, for
  example an external server started with `--no-slots`, or a server still loading its model.

The three figures at the bottom come from `llama-server`'s metrics:

| Figure         | Meaning                                                    |
| -------------- | ---------------------------------------------------------- |
| **Processing** | Requests being processed.                                  |
| **Queued**     | Requests waiting for a free slot.                          |
| **Busy slots** | Slots busy per decoding step, as reported by `llama-server`. |

## Recent requests

The **Recent requests** table lists the last 20 requests, newest first, since the server started. Restarting the
server, or switching to another profile, empties it.

| Column               | Meaning                                                                       |
| -------------------- | ----------------------------------------------------------------------------- |
| **Time**             | When the request was seen.                                                    |
| **Prompt**           | Prompt tokens processed.                                                      |
| **Cache**            | Prompt tokens reused from the cache instead of being processed again.         |
| **Generated**        | Tokens generated.                                                             |
| **Duration (s)**     | Prompt processing time plus generation time.                                  |
| **Prompt tok/s**     | Prompt speed of this request.                                                 |
| **Generation tok/s** | Generation speed of this request.                                             |
| **Acceptance**       | Share of drafted tokens accepted, for speculative decoding; `—` without it.   |

`llama-server` does not publish a per-request log. llama-webui rebuilds each row from the difference between two
samples of its counters, so the table is exact for one request at a time and approximate when several slots work at
once: requests that end within the same polling interval share one row.

If no request has been served yet, the card says **No requests since this server started.** The **Speculative
acceptance** tile, the queue figures and this table need `/metrics`: a server you started yourself without
`--metrics` does not report them.

## When no server runs

Without a running server, the Dashboard shows **llama-server is stopped** with a **Start** button that opens the
[Server](/docs/server/) page. The tiles, the chart, the slots and the requests disappear; the system strip keeps
measuring CPU, RAM, every visible GPU and the disks. Start a profile from [Home](/docs/home/) or the Server page and
the rest comes back on the next sample.

## Change the sampling

Both settings are on the **Monitoring** tab of [Settings](/docs/settings/), in the **Collection** card:

| Setting              | Default                    | Range                                  |
| -------------------- | -------------------------- | -------------------------------------- |
| **Polling interval** | 1000 ms                    | 250 ms, 500 ms, 1000 ms or 2000 ms     |
| **History kept**     | 300 s (shown as `5 min 00 s`) | 30 to 1,800 s, in steps of 30 s     |

A shorter interval makes the tok/s figures and the charts react faster. Changing either setting reshapes the history:
the most recent points are kept, and every open page reloads it.
