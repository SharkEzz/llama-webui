---
title: Installation
description: Install llama-webui on Linux from a release with npm, or run it from source, point it at your llama.cpp build, and open it in your browser.
---

llama-webui is a [Node.js](https://nodejs.org) application for Linux. Each release is an npm package that you
install with `npm install -g`, which gives you a `llama-webui` command. You can also run it from a clone of its
repository with [pnpm](https://pnpm.io). Either way, one Node.js process serves the API, the WebSocket and the
interface.

## What you need

| Requirement                                       | Why                                                                                                    |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **Linux**                                         | Hardware discovery and telemetry read `/proc` and `/sys`. `setpriv` (util-linux) ties `llama-server` to llama-webui. |
| **[Node.js](https://nodejs.org) 26.13 or later**  | Runs llama-webui. npm comes with it; [pnpm](https://pnpm.io) 12 is needed only to run from source.     |
| **A [llama.cpp](https://github.com/ggml-org/llama.cpp) build** | `llama-server` is required. `llama-bench`, next to it, enables benchmarks and sweeps.       |
| **GGUF models**                                   | In a folder of your choice, set during the first run.                                                  |

GPU telemetry is optional: NVIDIA cards are read through NVML (falling back to `nvidia-smi`), AMD cards through the
`amdgpu` driver's sysfs files. Without them, llama-webui still runs models and shows CPU and memory.
[Requirements](/docs/getting-started/requirements/) details each piece and what it unlocks.

## Install

<Steps>
  <Step title="Build llama.cpp">

If you already have a build with `llama-server`, keep it: llama-webui only needs the path to the binary. Otherwise,
build it for your GPUs. The binaries land in `build/bin/`.

<Tabs>
  <Tab title="NVIDIA (CUDA)">

Needs the CUDA toolkit.

```bash
git clone https://github.com/ggml-org/llama.cpp.git
cd llama.cpp
cmake -B build -DGGML_CUDA=ON
cmake --build build --config Release -j
```

  </Tab>
  <Tab title="AMD (ROCm)">

Needs ROCm. Set `GPU_TARGETS` to your card's architecture (`gfx1100` for a Radeon RX 7900), or leave it out to build
for every GPU in the machine.

```bash
git clone https://github.com/ggml-org/llama.cpp.git
cd llama.cpp
HIPCXX="$(hipconfig -l)/clang" HIP_PATH="$(hipconfig -R)" \
  cmake -S . -B build -DGGML_HIP=ON -DGPU_TARGETS=gfx1100 -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release -j
```

  </Tab>
  <Tab title="Vulkan">

Works with NVIDIA, AMD and Intel cards. Needs the Vulkan headers and `glslc`; check that `vulkaninfo` lists your GPUs
first.

```bash
git clone https://github.com/ggml-org/llama.cpp.git
cd llama.cpp
cmake -B build -DGGML_VULKAN=ON
cmake --build build --config Release -j
```

  </Tab>
  <Tab title="CPU only">

```bash
git clone https://github.com/ggml-org/llama.cpp.git
cd llama.cpp
cmake -B build
cmake --build build --config Release -j
```

  </Tab>
</Tabs>

Backends can be combined in one build, for example `-DGGML_CUDA=ON` and `-DGGML_VULKAN=ON` for a machine with NVIDIA and AMD
cards: llama-webui then lists every device and can split a model across them.

  </Step>
  <Step title="Install Node.js">

llama-webui needs Node.js 26.13 or later. Check the version you have:

```bash title="Terminal"
node --version
```

If it is older, or missing, install a current release with a version manager such as [fnm](https://github.com/Schniz/fnm)
(`fnm install 26`) or from [nodejs.org](https://nodejs.org/en/download). With a version manager, npm installs global
packages into your home folder. With the Node.js of your distribution, they would go to a system folder: point npm at
your home once, and make sure `~/.local/bin` is in your `PATH`:

```bash title="Terminal"
npm config set prefix ~/.local
```

  </Step>
  <Step title="Get llama-webui">

<Tabs>
  <Tab title="Release">

Each [release](https://github.com/SharkEzz/llama-webui/releases) holds the package, `llama-webui-<version>.tgz`, and
the SHA-256 of its files, `SHA256SUMS`. Set `VERSION` to the latest release (without the `v`), download both, check
the package and install it:

```bash title="Terminal"
VERSION=x.y.z   # the latest release, for example 1.2.3
BASE=https://github.com/SharkEzz/llama-webui/releases/download/v$VERSION
curl -fL -O "$BASE/llama-webui-$VERSION.tgz" -O "$BASE/SHA256SUMS"
sha256sum -c SHA256SUMS
npm install -g "./llama-webui-$VERSION.tgz"
```

npm copies the package, so you can delete the two files afterwards. It also installs the three libraries llama-webui
uses for HTTP and WebSocket, at the exact versions the release was tested with; everything else is bundled.

  </Tab>
  <Tab title="From source">

Needs [pnpm](https://pnpm.io) 12 (`npm install -g pnpm`, or `corepack enable pnpm`).

```bash title="Terminal"
git clone https://github.com/SharkEzz/llama-webui.git
cd llama-webui
pnpm install
```

  </Tab>
</Tabs>

  </Step>
  <Step title="Start it">

<Tabs>
  <Tab title="Release">

```bash title="Terminal"
llama-webui
```

  </Tab>
  <Tab title="From source">

```bash title="Terminal"
pnpm start
```

`pnpm start` builds the interface (a few seconds), then starts the server.

  </Tab>
</Tabs>

When it prints `llama-webui on http://127.0.0.1:7860`, open that address in your browser.

  </Step>
</Steps>

On the first launch, Home opens a setup checklist: it looks for `llama-server` (or asks for its path), checks the
models folder, lists what `llama-bench` and the GPU telemetry can see, and reviews the machine configuration. Only the
binary and the models folder are required. [First run](/docs/getting-started/first-run/) goes through each step.

## Open it from another machine

llama-webui listens on `127.0.0.1` by default, so only the machine it runs on can reach it. To use it from a laptop on
the same network, listen on every interface, then open `http://<server-address>:7860`:

```bash title="Terminal"
llama-webui --host 0.0.0.0        # from source: pnpm start --host 0.0.0.0
```

<Callout type="warning" title="No authentication">

Whoever can reach llama-webui can start processes on your machine. The API rejects cross-site requests and
DNS-rebinding attempts, but only use `--host 0.0.0.0` on a network you trust, and never expose it to the internet.
[Security](/docs/security/) explains what is exposed and how to use an SSH tunnel instead.

</Callout>

`--port` changes the port and `--data-dir` the folder that holds the database. Each flag has an environment variable
(`LLAMA_WEBUI_HOST`, `LLAMA_WEBUI_PORT`, `LLAMA_WEBUI_DATA_DIR`); `llama-webui --help` (or `pnpm start --help`)
lists them, and [Launch options](/docs/configuration/) describes each one.

## Run it as a service

A systemd user service starts llama-webui with your session and restarts it if it stops. It runs as your user, so
`llama-server` can read your models and GPUs as it does from a terminal.

A service does not get the `PATH` of your terminal, so the unit names Node.js and llama-webui by their full paths.
This command writes it with the paths of your installation filled in:

```bash title="Terminal"
mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/llama-webui.service <<EOF
[Unit]
Description=llama-webui

[Service]
WorkingDirectory=%h
ExecStart=$(realpath "$(command -v node)") $(npm prefix -g)/bin/llama-webui
Restart=on-failure

[Install]
WantedBy=default.target
EOF
```

The `ExecStart` line then reads, for example,
`ExecStart=/usr/bin/node /home/you/.local/bin/llama-webui`. If you later move to another Node.js version with a
version manager, install llama-webui again with it and write the unit again.

From source, build once with `pnpm build`, point `WorkingDirectory` at the clone (`%h/llama-webui`) and start the
built server: `ExecStart=/usr/bin/node %h/llama-webui/dist/server/main.js`, with the path of your `node`.

```bash title="Terminal"
systemctl --user daemon-reload
systemctl --user enable --now llama-webui
journalctl --user -u llama-webui -f   # follow its output
```

User services stop when you log out. To keep llama-webui running without a session, for example on a headless
server, enable lingering once:

```bash
loginctl enable-linger "$USER"
```

<Callout type="note">

`llama-server` is tied to llama-webui: stopping the service, or llama-webui crashing, stops the model too, so no
orphan process keeps your VRAM.

</Callout>

## Update

The status bar, at the top right of every page, shows the version that runs: the release tag (or the short commit
hash of the build), `dev` from source. To update a release, run the commands of
[Get llama-webui](#install) again with the new `VERSION`: `npm install -g` replaces the installed version. From
source:

```bash title="Terminal"
cd llama-webui
git pull
pnpm install
pnpm build   # for the service; pnpm start builds by itself
```

Then restart llama-webui (`systemctl --user restart llama-webui` for the service). The database is migrated on
startup: profiles, conversations, benchmark runs and settings are kept.

## Uninstall

Stop llama-webui, then remove the package (or delete the clone) and the data folder (`$XDG_DATA_HOME/llama-webui`,
by default `~/.local/share/llama-webui`). Your models and your llama.cpp build are never touched.

```bash title="Terminal"
npm uninstall -g llama-webui        # from source: rm -rf ~/llama-webui
rm -rf ~/.local/share/llama-webui
```

For the service, also run `systemctl --user disable --now llama-webui` and delete
`~/.config/systemd/user/llama-webui.service`.
