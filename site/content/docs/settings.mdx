The Settings page holds the options you change while llama-webui runs: where `llama-server` and your models are, how
the monitoring samples the machine, and the theme. Open it from **Settings** at the bottom of the sidebar. Options
that must be known before llama-webui starts (its own address, port and data folder) are
[launch options](/docs/configuration/) instead.

## How settings are saved

Each option is saved on its own, as soon as you change it; there is no Save button.

- **Text fields** are saved when you press <Kbd>Enter</Kbd> or leave the field, if the value changed. Leading and
  trailing spaces are removed.
- **Switches, menus and the slider** are saved when you change them (the slider when you release it).
- **Environment variables** are saved when you leave the box, if they changed and every line is valid.

A **Setting saved** notification confirms each change. An invalid value is not saved: its error appears under the
field, for example "Port between 1 and 65535". Settings are stored in llama-webui's database, so they are the same in
every browser, except the [debug mode](#developer), which each browser keeps for itself.

The **Run setup again** button, at the top of the page, reopens the [setup checklist](/docs/getting-started/first-run/).

## General

The **llama-server** card tells llama-webui where to find `llama-server` and your models, and where `llama-server`
listens by default.

| Field             | Default        | Effect                                                                                                                                                                                                             |
| ----------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Binary**        | `llama-server` | The `llama-server` to run: an absolute path (`~` for your home works), or a name found in the `PATH`. Also used to read its build number and its `--help`, and to find `llama-bench` in the same folder.           |
| **Models folder** | `~/models`     | The folder scanned for GGUF files, with its subfolders. [Hugging Face downloads](/docs/hugging-face/) are saved there, and it becomes the working directory of a new profile when you pick its model.              |
| **Default host**  | `127.0.0.1`    | The `--host` given to `llama-server` for profiles that leave **Host** empty. Below the field, a warning says when it opens `llama-server` to your network.                                                         |
| **Default port**  | `8080`         | The `--port` given to `llama-server` for profiles that leave **Port** empty. Also the port of the temporary servers of benchmark runs, and the port where llama-webui looks for a `llama-server` it did not start. |

Changes apply to the next start: a running `llama-server` keeps its binary, host and port until you restart it.

<Callout type="important" title="Reach llama-server from other machines">

With the default host `127.0.0.1`, only this machine can use the model's API. Set **Default host** to `0.0.0.0` (every
interface) or to one of this machine's addresses to reach it from your network: anyone who can reach the port can then
send prompts to the model. Earlier versions defaulted to `0.0.0.0`: if you relied on it, set it again here.
See [Security](/docs/security/#how-llama-server-is-exposed).

</Callout>

### Environment variables

The **Environment variables** card, under the llama-server card, takes one `KEY=value` per line, for example `CUDA_VISIBLE_DEVICES=0,1` or
`GGML_CUDA_P2P=1`. Empty lines are ignored; a line without `=` or with an invalid name shows an error and nothing is
saved until you fix it. Removing a line removes the variable.

These variables are given to every profile you start, and to benchmark runs and [Tuning](/docs/tuning/) sweeps
(`llama-server` and `llama-bench` alike), on top of the environment llama-webui was started with. A
[profile](/docs/profiles/#environment-variables) variable with the same name wins. A running `llama-server` keeps its
environment until you restart it.

## Monitoring

The Monitoring tab controls what llama-webui reads from the machine, how often, and how much history it keeps.

<Screenshot
  name="settings-monitoring"
  alt="The Monitoring tab: a Collection card with switches for NVML for NVIDIA GPUs, CPU and memory, and Disks, a Polling interval menu set to 1000 ms and a History kept slider at 5 min 00 s; a Displayed GPUs card with one switch per graphics card and its PCI address, the integrated Radeon 610M switched off."
/>

### Collection

| Option                   | Default | Effect                                                                                                                                                  |
| ------------------------ | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **NVML for NVIDIA GPUs** | On      | Reads NVIDIA cards through NVML. Off: through `nvidia-smi`, which gives no PCIe bandwidth, clocks or fans. **Applied on the next llama-webui start.**   |
| **CPU and memory**       | On      | CPU usage, memory, and the DRAM bandwidth measured with `perf`. Off: none of them is read, and `perf` is stopped.                                       |
| **Disks**                | On      | Read and write rates of the disks, including the reads from the disk that holds the running model.                                                      |
| **Polling interval**     | 1000 ms | How often every collector is read and the figures are sent to your browser: 250 ms, 500 ms, 1000 ms or 2000 ms. A new sample arrives once per interval. |
| **History kept**         | 5 min   | How far back the live charts of the Dashboard and the System page go, from 30 s to 30 min in steps of 30 s.                                             |

Apart from the NVML switch, these options take effect at once. The history is kept in llama-webui's memory, not in the
browser: a page you open later still shows the last minutes, but restarting llama-webui empties it. Monitoring never
writes to the database.

The `llama-server` figures (tokens per second, slots, context) are read at every interval as long as a server runs;
they have no switch.

### Displayed GPUs

One switch per GPU llama-webui detected, with its name, PCI address and VRAM. All cards are shown by default. A
hidden card is no longer read: it disappears from the Dashboard gauges, the System page marks it as hidden, and a card
that is asleep is not woken up. Use it for an integrated GPU, or a card you keep for another task. The same
switches appear in the setup checklist.

Hiding a card only changes what llama-webui reads. `llama-server` can still use it: to keep a model off a card, use
the profile's flags or environment variables (see [Profiles](/docs/profiles/)).

## Appearance

The **Theme** card has one option, **Interface theme**:

| Value      | Effect                                                     |
| ---------- | ---------------------------------------------------------- |
| **System** | Default. Follows the light or dark setting of your system. |
| **Light**  | Always light.                                              |
| **Dark**   | Always dark.                                               |

The theme button at the top right of every page sets the same option. The choice is saved in your browser and in
llama-webui's database; when a page loads, the database value wins, so a theme chosen in one browser follows you to
the others.

## Developer

The **Debug** card has one switch, **Debug mode**, off by default. It is saved in your browser only: turning it on in
one browser does not turn it on in another, nor in another llama-webui instance opened from this browser on another
address.

While it is on, a round button with a code icon sits at the bottom right of every page (notifications move up above
it). It opens the **Debug** window, and so does <Kbd>Alt</Kbd>+<Kbd>Shift</Kbd>+<Kbd>D</Kbd> from anywhere in the page:
a floating window that stays open from one page to the next, and is closed again after a reload. Drag it by its title
to move it, and by its right edge, its bottom edge or its bottom right corner to resize it; it reopens where you left
it. The pause button freezes what the window shows (the capture goes on), the eraser empties it, and <Kbd>Esc</Kbd>,
the shortcut or the cross closes it. While the window is closed, a red badge on the button counts the messages the page
rejected and the API calls that failed.

| Tab             | What it shows                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **WebSocket**   | The connection: its status and address, since when it is open, the reconnections, the delay before the next attempt, the last close and its code, the gap between the server's clock and the page's, the server's boot ids. Then each message type with its count, its rate, its total size and how many parts of the page listen to it, and the last messages, filterable by type and searchable by content, each one opening on its content; a message the page rejects is in red with the reason. |
| **HTTP**        | The API calls, those in flight first: method, path, status (or the error), time to the response headers, total time and size; each one opens on what it sent and what it received. **errors only** keeps the failed calls.                                                                                                                                                                                                                                                                           |
| **SSE**         | The server-sent event streams (a chat reply opens one): the time to the first event, the events by type, the characters received and their rate, how the stream ended and, once the reply is done, llama-server's own measures (prompt and reply tokens, tokens per second, cached tokens, time to the first token); each one opens on its last events.                                                                                                                                              |
| **Performance** | The frame rate and the JavaScript heap (Chromium) over the last minute, sampled while the window is open; the page's largest paint and layout shifts (CLS) with their Web Vitals rating; the long tasks; the slowest and the last interactions over 40 ms; the time each of the last navigations took to render; and the React renders of the sidebar, the status bar and each page: commits, commits since the last navigation, mounts, mean, worst, last and base duration.                        |
| **Loads**       | The page's load (first byte, DOM ready, load event, size of the document) and each file it loaded besides the API calls, filterable by type: scripts (each page's code is loaded when you first open it), style sheets, fonts, images, with their transferred size (or the cache), their size and their time.                                                                                                                                                                                        |
| **Stores**      | The page's stores (the settings, the server, the chat, the monitoring…), those loaded so far: each one with its changes, their rate and its `set()` calls that changed nothing. Select one to browse its state as a tree, opened branch by branch, with the names of its actions, or its changes; **All stores** lists every change, newest first, filterable by key, each one opening on what it changed, path by path, the value before struck through and the value after.                        |
| **Environment** | The version, build, boot id, address, browser, language and time zone, viewport and screen, theme, and the CPU threads and JavaScript heap of the browser's machine.                                                                                                                                                                                                                                                                                                                                 |

The download button exports everything the window holds, the environment, the capture and the stores, as one JSON
file (`llama-webui-debug-<date>.json`) to attach to an issue. By default the file leaves out the text of your
conversations (replaced by its length), your home folder (`<home>`), the values of environment variables and of
`--api-key` or `--hf-token` (`<hidden>`), and the values of the stores' changes (which keys changed stays).
**Include private data** exports them as they are. Read the file before you
publish it: a model's name, a folder outside your home or, at a verbose log level, a prompt in the llama-server logs
stays.

Nothing is captured while the debug mode is off; turning it on starts from empty. The largest paint, the layout
shifts and the files loaded also list what the browser kept from the page's load. React only times renders in a
development build (`pnpm dev`, see [Web app](/developers/frontend/#debug-window)): in an installed llama-webui the
render table stays empty. The capture keeps a bounded number of entries (the last 500 WebSocket messages, 300 API
calls, 50 streams, 300 files, the last 200 changes of each store) and costs a little CPU while it runs: turn the debug mode off before measuring the app's
performance.

## Values saved without a field

llama-webui also stores a few values in its settings that have no field on this page:

- whether the setup checklist is finished (or skipped), which decides whether `/` shows the checklist or the Dashboard;
- the last profile you started, preselected on the [Server](/docs/server/) page.
