llama-webui has one HTTP API. Its own web app uses it, and so can your scripts and integrations. It is declared once,
with Effect's `HttpApi`, in `packages/webui-shared/src/api/` (`@llama-webui/shared`): `Api` (`api/Api.ts`) is made of
one group per domain (`ProfilesApi`, `BenchApi`…), and each endpoint states its path, its parameters, its body, its
query, its reply and the errors it can answer, as schemas. The server implements that declaration
(`app/server/<domain>/http.ts`), and the web app derives its client from it.

## Base URL

One Node.js process serves the API, the WebSocket and the web app on one address, `http://127.0.0.1:7860` by default.
`--host` and `--port`, or `LLAMA_WEBUI_HOST` and `LLAMA_WEBUI_PORT`, change it: see
[Launch options](/docs/configuration/).

- REST endpoints are under `/api/`.
- The WebSocket is `/ws`.
- Any other path serves the web app (`index.html` for any path that is not a file, so reloading `/chat` works).

There is no authentication and no API key: anyone who can reach the port can call every endpoint. The examples on
these pages use `http://127.0.0.1:7860`.

## Channels

| Channel            | Where                                                                                      | Carries                                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| REST               | `/api/*`                                                                                   | Reads and commands, JSON in and out.                                                                                                    |
| WebSocket          | `/ws`                                                                                      | Events pushed by the server: monitor snapshots, log lines, server state, benchmark, sweep and download progress.                        |
| Server-sent events | `POST /api/chat/:id/messages`, `POST /api/chat/:id/regenerate`, `GET /api/chat/:id/stream` | The events of a chat reply while it is generated (`event: <type>` then `data: <json>`, a `: ping` comment after 15 seconds of silence). |

The WebSocket only sends `hello` when a client connects, then events as they happen. A client reads the current state
over REST and applies the messages on top of it: see [WebSocket](/developers/api/websocket/). The chat streams are
described on [Chat](/developers/api/chat/).

## The request guard

Every `/api/*` request and every `/ws` request go through the guard (`app/server/http/Guard.ts`) before anything
else, an unknown path included, and whatever the spelling of the path the server accepts (`/API/health`,
`//api/health`). The API is unauthenticated and local, so the guard protects it from other websites
open in your browser. It does not protect it from people on your network. It applies three checks, in this order:

| Check          | Rule                                                                                                                                                                            | Refusal                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `Host`         | The header parses as a host, and its hostname is `localhost`, ends in `.localhost`, or is an IPv4 or IPv6 literal.                                                              | `403` `Host not allowed`; `400` `Invalid host` when it does not parse |
| `Origin`       | When the header is present, it equals `http://<Host header>` exactly.                                                                                                           | `403` `Origin not allowed`                                            |
| `content-type` | For `POST`, `PUT`, `PATCH` and `DELETE`: a `content-type`, when sent, is `application/json` (parameters such as `; charset=utf-8` allowed), and a request with a body sends it. | `415` `JSON body expected (content-type: application/json)`           |

- The `Host` rule stops DNS rebinding: a domain name can be made to resolve to `127.0.0.1`, an IP address cannot. The
  API therefore refuses requests addressed by host name, such as `http://myserver.lan:7860`.
- The `Origin` rule stops cross-site requests, a WebSocket opened by another site included. `curl` and most
  non-browser clients send no `Origin`, so they pass.
- The `content-type` rule stops "simple request" CSRF: another site can make the browser post a form or a plain-text
  body without asking, but `application/json` needs a CORS preflight, which llama-webui never grants. A write without
  a body and without a `content-type` passes (`curl -X POST http://127.0.0.1:7860/api/server/stop`).

A refusal is an error like any other, tagged `RequestRefused`:

```bash title="Terminal"
curl -i http://127.0.0.1:7860/api/health -H 'Origin: http://example.com'
```

```text
HTTP/1.1 403 Forbidden
content-type: application/json

{"_tag":"RequestRefused","message":"Origin not allowed"}
```

The API sends no CORS headers either, so a browser does not let another site read its responses. The reasons behind
each rule are on [Security](/developers/server/security/), and the user-facing summary on
[Security](/docs/security/).

## Errors

Every `/api/*` error is a JSON object with a `_tag`, the name of the error, and a `message` written for people:

```json
{ "_tag": "ProfileNameTaken", "message": "A profile named “Qwen3 32B” already exists" }
```

Each error is a `Schema.TaggedError` of the shared package, and its status is part of its declaration
(`httpApiStatus`). An endpoint lists the errors it can answer (`error: [ProfileNotFound, ProfileNameTaken]`), and the
API reference pages list them with each endpoint. A few carry more fields: `PortInUse` also has `port`, and `by` and
`pid` when the port's owner is known; `RequestInvalid` and `SettingsInvalid` have `issues`.

Match on the status and the `_tag`, never on the `message` text: messages are written for people and can change. The
web app follows the same rule (`errorTag()` in `app/src/lib/api.ts`).

These errors are the same on every endpoint:

| `_tag`           | Status              | When                                                                                        |
| ---------------- | ------------------- | ------------------------------------------------------------------------------------------- |
| `RequestRefused` | `400`, `403`, `415` | The [request guard](#the-request-guard) refused the request.                                |
| `RouteNotFound`  | `404`               | `Unknown route`: no endpoint has this path and method, or a path parameter does not decode. |
| `RequestInvalid` | `400`               | The body, the query or a header does not decode ([Validation errors](#validation-errors)).  |

An exception in a handler (a bug, not an error the endpoint declares) is logged on the server's console with its
cause, and the client gets a `500` without its message.

### Validation errors

A body, a query or a header that does not decode is answered before the handler runs: a `400` `RequestInvalid` with
the first issue in `message` (its path in parentheses, when it has one) and every issue in `issues`, each a `path`
(the keys and indexes, as strings) and a `message`:

```json
{
  "_tag": "RequestInvalid",
  "message": "Invalid data: unknown key (extra)",
  "issues": [
    { "path": ["extra"], "message": "unknown key" },
    { "path": ["name"], "message": "cannot be empty" }
  ]
}
```

This one comes from `POST /api/profiles` with an empty `name` and a key the profile does not have. Bodies are decoded
strictly: an unknown key is an issue, and every issue is reported, not just the first. A body that is not JSON is
`Invalid data: Expected a valid JSON body`, a JSON value that is not an object (or no body at all) `Invalid data:
Expected object`. The web app shows each issue under the field its first `path` segment names.

`PATCH /api/settings` checks the merged settings after the decode, and answers a value out of range with its own
`400` `SettingsInvalid` `Invalid settings`, with the same `issues`.

### Error tags

Before the move to Effect, a few errors carried a machine-readable `code`. Each is now a `_tag`:

| Former `code`                                                                      | `_tag`                                                                                                            | Status                            |
| ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| `name-taken`                                                                       | `ProfileNameTaken` ([Profiles](/developers/api/profiles/))                                                        | `409`                             |
| `server-running`                                                                   | `ServerRunning` ([Benchmarks](/developers/api/bench/))                                                            | `409`                             |
| `hf-gated`, `hf-not-found`, `hf-unauthorized`, `hf-rate-limited`, `hf-unreachable` | `HfGated`, `HfNotFound`, `HfUnauthorized`, `HfRateLimited`, `HfUnreachable` ([Hugging Face](/developers/api/hf/)) | `403`, `404`, `401`, `429`, `502` |
| `already-queued`, `not-finished`                                                   | `AlreadyQueued`, `NotFinished` ([Hugging Face](/developers/api/hf/))                                              | `409`                             |
| `disk-full`                                                                        | `DiskFull` ([Hugging Face](/developers/api/hf/))                                                                  | `507`                             |

## Status codes

| Status | Meaning in this API                                                                                                                                   |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `200`  | Success, with a JSON body.                                                                                                                            |
| `201`  | A resource was created (profile, duplicate, conversation, profile from a benchmark run); the body is the new resource.                                |
| `202`  | The operation started and goes on in the background (server start, switch and restart, benchmark run, sweep, download); follow it over the WebSocket. |
| `204`  | Success without a body (deletions, cancellations, a chat stream with no reply in progress).                                                           |
| `308`  | A path under `/api/` or `/ws/` that ends with a slash: `Location` is the same path without it, the query kept.                                        |
| `400`  | A body, a query or a header that does not decode (`RequestInvalid`); invalid settings; a `Host` header that does not parse (`Invalid host`).          |
| `401`  | Hugging Face rejected the token (`HfUnauthorized`).                                                                                                   |
| `403`  | Refused by the guard (`Host`, `Origin`), or a gated Hugging Face repository.                                                                          |
| `404`  | Unknown route (a path, a method a path does not have, `HEAD` included, or a path parameter that is not an id), unknown id, or missing file.           |
| `409`  | The request conflicts with the current state: a name is taken, an operation is in progress, a benchmark holds the GPUs, a server is running…          |
| `415`  | Refused by the guard: a write that is not `application/json`.                                                                                         |
| `422`  | The file exists but cannot be read as a GGUF.                                                                                                         |
| `426`  | `/ws` requested without a WebSocket upgrade (plain-text body `WebSocket upgrade expected`).                                                           |
| `429`  | Hugging Face rate limit reached (`HfRateLimited`).                                                                                                    |
| `500`  | An exception in a handler: logged on the server, answered without its message.                                                                        |
| `502`  | An upstream service failed: `llama-server` (`/props`) or Hugging Face.                                                                                |
| `503`  | `llama-server --help` failed (`/api/flags`, `FlagsUnavailable`).                                                                                      |
| `507`  | Not enough disk space for a download (`DiskFull`).                                                                                                    |

There is no `405`: a method a path does not define is the `404` `RouteNotFound` of an unknown path. There is no `503`
"starting" either: the port opens once every service is built, so a request always finds the server ready.

## How routes are registered

An endpoint is declared in its group, in `packages/webui-shared/src/api/<Domain>Api.ts`:

```ts title="packages/webui-shared/src/api/ProfilesApi.ts"
const params = { id: IdParam };

export class ProfilesApi extends HttpApiGroup.make('profiles').add(
  HttpApiEndpoint.get('list', '/api/profiles', { success: Schema.Array(Profile) }),
  HttpApiEndpoint.post('create', '/api/profiles', {
    payload: ProfileInput,
    success: Created,
    error: ProfileNameTaken,
  }),
  HttpApiEndpoint.put('update', '/api/profiles/:id', {
    params,
    payload: ProfileInput,
    success: Profile,
    error: [ProfileNotFound, ProfileNameTaken],
  }),
  // …
) {}
```

Its handler is in `app/server/<domain>/http.ts` (`HttpApiBuilder.group(Api, 'profiles', …)`), and each group's
handlers are merged in `ApiRoutes` (`app/server/http/HttpLive.ts`). A request is answered in this order:

1. The [request guard](#the-request-guard).
2. A trailing slash under `/api/` is a `308` to the path without it.
3. The router finds the endpoint by method and path; a static segment wins over a `:id`
   (`GET /api/profiles/export` is not `GET /api/profiles/:id`). No endpoint: `404` `RouteNotFound`.
4. The path parameters are decoded: an `:id` is `IdParam`, a positive integer written in digits, and anything else
   (`/api/profiles/abc`, `/api/profiles/0`) is the `404` `RouteNotFound`, the answer of a path that does not exist.
5. The query, the headers and the body are decoded with the endpoint's schemas: a failure is the `400`
   `RequestInvalid`. Since this happens before the handler, a malformed body is a `400` even for an id that does not
   exist or a resource that is busy.
6. The handler runs, and answers its `success` (encoded with its schema) or one of its declared errors.

A query value is a string in the URL: its schema decodes it (`since` of `GET /api/logs` is a `SeqParam`, so `?since=abc`
is a `400`). A JSON file to download is `attachment(schema)` (`app/server/http/attachment.ts`), which adds the
`Content-Disposition`; an SSE stream is `HttpApiSchema.StreamSse` with `sseResponse` (`app/server/http/Sse.ts`).

### Typed client

The web app calls the API through `call()` (`app/src/lib/api.ts`), made from `Api` with Effect's `HttpApiClient`:

```ts title="app/src/lib/logs.ts"
const r = await call((api) => api.logs.list({ query: { since: asked.seq } }));
```

The call resolves with the reply decoded by the endpoint's `success` schema, and rejects with one of the endpoint's
tagged errors, decoded from the response, or with `ApiUnreachable` when no response came. A body the client's schema
refuses is not sent: the call rejects with the same `RequestInvalid` the server would answer. `callStream(…, onEvent,
{ signal })` reads an SSE endpoint, one decoded event at a time.

Every type comes from the declaration: `params`, `payload` and `query` are typed by their schemas' encoded side, the
reply by `success`, the errors by `error`. The web never casts a reply. The one endpoint whose reply is not described,
`GET /api/server/props` (llama-server's own JSON, `Schema.Unknown`), is narrowed by guards (`app/src/lib/props.ts`).

To add an endpoint, see [How-to guides](/developers/contributing/how-to/).

## Conventions

- **JSON everywhere.** Bodies are JSON, sent with `content-type: application/json`. Responses are JSON, except a `204`
  (no body), a `308` (no body), the chat event streams (`text/event-stream`), the profile exports (a JSON file sent as
  an attachment) and the `426` of `/ws` (plain text).
- **Ids** are SQLite integer ids (`id INTEGER PRIMARY KEY`), positive integers in paths (`/api/profiles/3`) and numbers
  in bodies (`{"profileId": 3}`, never `"3"`).
- **Times** are epoch milliseconds: `createdAt`, `updatedAt`, `finishedAt`, `since`, `at`, `scannedAt`, `serverTime`.
- **Durations** carry their unit in their name: `uptimeMs`, `durationMs` and `pollIntervalMs` are milliseconds,
  `historySeconds` is seconds, `promptSec` and `genSec` are seconds.
- **Sizes** are bytes, named `…Bytes` (`fileBytes`, `vramBytes`, `rssBytes`), and rates are bytes per second, named
  `…Bps` (`readBps`, `diskReadPeakBps`). The exceptions are in MiB and say so: `BenchDevice.totalMib` and
  `BenchDevice.freeMib` (as `llama-bench --list-devices` reports them) and `BenchRun.vramPeak[].mib`.
- **`null` and absent fields.** A field typed `T | null` is always present, and `null` means unknown, not applicable
  or not set (`SetupReport.binary.path`, `ServerView.command`, `GpuSample.tempC`). An optional field is left out
  when it has no value, never sent as `null`: the optional fields of a profile (`mmproj`, `cwd`, `host`, `port`),
  `Flag.value` for a switch. A few monitor fields accept both (`GpuSample.fanPct`): missing or `null` both mean
  unknown.
- **Paths** are absolute paths on the machine that runs llama-webui. The server expands `~` and `~/…` in the models
  folder setting and in a profile's `model`, `mmproj` and `cwd`.
