These pages are for developers who want to understand llama-webui's internals, change or extend it, or drive it from
another program through its API. They name files, modules, types and constants, and they follow the code: when the
two disagree, the code is right and the page is a bug.

If you only want to install and use llama-webui, start with the [user documentation](/docs/) instead.

## The repository

llama-webui is a Bun monorepo with four workspaces and a separate website. `server/` is the Bun process: it serves the
REST API, the `/ws` WebSocket and the web UI on one port (7860 by default), supervises one `llama-server`, samples the
hardware, runs benchmarks and sweeps, relays chat generations and stores everything in a SQLite file. `web/` is the
React app it serves. `packages/` holds the libraries: `packages/webui-shared/` (the `@llama-webui/shared` package) has
the types, zod schemas and pure functions both sides use, and `packages/llamacpp-js/` everything that talks to
llama.cpp (its HTTP API, its metrics, the output of its binaries), written to be published on its own. `site/` is this
website, a standalone package outside the workspaces.
[Development setup](/developers/getting-started/#repository-layout) shows the layout in detail.

## Tech stack

| Layer | Technology | Where |
| --- | --- | --- |
| Runtime | [Bun](https://bun.com) 1.4.4 or later: HTTP and WebSocket server (`Bun.serve`), bundler (`Bun.build`, HTML imports), test runner, `bun:ffi` | the whole repository |
| HTTP API | [Hono](https://hono.dev) 4 with `@hono/zod-validator`: one chained app for every `/api` route, served by `Bun.serve` | `server/api.ts`, `server/routes/` |
| Database | `node:sqlite` behind a wrapper (`server/db/sqlite.ts`), one file in the data directory, WAL journal | `server/db/` |
| Validation | [zod](https://zod.dev) 4: request bodies and settings are parsed on the server, TypeScript types are inferred for both sides | `packages/webui-shared/src/`, `server/` |
| GGUF headers | `@huggingface/gguf` | `server/models/`, `server/hf/` |
| UI | [React](https://react.dev) 19, [React Router](https://reactrouter.com) 8 (data router, lazy routes) | `web/` |
| Styling | [Tailwind CSS](https://tailwindcss.com) 4 through `bun-plugin-tailwind` | `web/src/index.css` |
| Components | [shadcn/ui](https://ui.shadcn.com) (`base-nova` style) on [Base UI](https://base-ui.com), lucide icons, sonner toasts, cmdk | `web/src/components/ui/` |
| State | [zustand](https://zustand.docs.pmnd.rs) 5, one store per domain | `web/src/lib/` |
| Charts and 3D | [uPlot](https://github.com/leeoniya/uPlot) time series, [react-three-fiber](https://r3f.docs.pmnd.rs) and three.js for the Topology page | `web/src/components/charts/`, `web/src/features/topology/` |
| Text | react-markdown and remark-gfm for chat replies, [Shiki](https://shiki.style) for code blocks | `web/src/features/chat/`, `web/src/lib/highlight.ts` |
| Quality | TypeScript 7 (`bun check`), [Biome](https://biomejs.dev) 2 (format, lint, imports), `bun test` | `biome.json`, `tsconfig.json` |

The website uses its own stack (Vite, React Router in framework mode with prerendering, MDX): it is the one place in
the repository where Vite is allowed.
