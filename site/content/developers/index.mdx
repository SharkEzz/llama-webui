These pages are for developers who want to understand llama-webui's internals, change or extend it, or drive it from
another program through its API. They name files, modules, types and constants, and they follow the code: when the
two disagree, the code is right and the page is a bug.

If you only want to install and use llama-webui, start with the [user documentation](/docs/) instead.

## The repository

llama-webui is a pnpm monorepo: three workspaces for the app and one for the website. `app/` is the app, one Node.js
process built with [Nitro](https://nitro.build): its server, in `app/server/`, serves the REST API, the `/ws` WebSocket
and the web UI on one port (7860 by default), supervises one `llama-server`, samples the hardware, runs benchmarks and
sweeps, relays chat generations and stores everything in a SQLite file; its React client is in `app/src/`.
`packages/` holds the libraries: `packages/webui-shared/` (the `@llama-webui/shared` package) has the types, zod schemas and pure functions both sides use, and `packages/llamacpp-js/` everything that talks to
llama.cpp (its HTTP API, its metrics, the output of its binaries), written to be published on its own. `site/` is this
website, which imports no code of the app.
[Development setup](/developers/getting-started/#repository-layout) shows the layout in detail.

## Tech stack

| Layer | Technology | Where |
| --- | --- | --- |
| Runtime | [Node.js](https://nodejs.org) 26.13 or later, one process for the API, the WebSocket and the UI | `app/server/` |
| Build | [Vite](https://vite.dev): `vite dev` with HMR, `vite build` for the web client and, through Nitro's plugin, the server | `app/vite.config.ts` |
| Server | [Nitro](https://nitro.build) 3 (h3, srvx, [crossws](https://crossws.h3.dev) for the WebSocket): one file per `/api` route, middlewares for the guard and the `405` table, a typed client generated from the routes | `app/server/routes/`, `app/server/middleware/`, `app/server/api.gen.ts` |
| Database | `node:sqlite` behind a wrapper (`app/server/lib/db/sqlite.ts`), one file in the data directory, WAL journal | `app/server/lib/db/` |
| Validation | [zod](https://zod.dev) 4: request bodies and settings are parsed on the server, TypeScript types are inferred for both sides | `packages/webui-shared/src/`, `app/server/lib/` |
| GGUF headers | `@huggingface/gguf` | `app/server/lib/models/`, `app/server/lib/hf/` |
| UI | [React](https://react.dev) 19, [React Router](https://reactrouter.com) 8 (data router, lazy routes) | `app/src/` |
| Styling | [Tailwind CSS](https://tailwindcss.com) 4 through `@tailwindcss/vite` | `app/src/index.css` |
| Components | [shadcn/ui](https://ui.shadcn.com) (`base-nova` style) on [Base UI](https://base-ui.com), lucide icons, sonner toasts, cmdk | `app/src/components/ui/` |
| State | [zustand](https://zustand.docs.pmnd.rs) 5, one store per domain | `app/src/lib/` |
| Charts and 3D | [uPlot](https://github.com/leeoniya/uPlot) time series, [react-three-fiber](https://r3f.docs.pmnd.rs) and three.js for the Topology page | `app/src/components/charts/`, `app/src/features/topology/` |
| Text | react-markdown and remark-gfm for chat replies, [Shiki](https://shiki.style) for code blocks | `app/src/features/chat/`, `app/src/lib/highlight.ts` |
| Quality | TypeScript 7 (`tsc`), [Biome](https://biomejs.dev) 2 (format, lint, imports), [Vitest](https://vitest.dev) and `node:test` | `biome.jsonc`, `tsconfig.base.json`, `vitest.config.ts` |

The website uses its own stack (Vite, React Router in framework mode with prerendering, MDX), and its scripts run
on Node.js like the app's.
