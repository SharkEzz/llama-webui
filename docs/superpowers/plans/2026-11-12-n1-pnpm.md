# N1 — pnpm workspace, single lockfile: task plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** pnpm installs the whole repo (app workspaces + `site/`) from one `pnpm-lock.yaml`; Bun still runs everything.

**Architecture:** `pnpm-workspace.yaml` declares the five projects, a catalog for the versions two or more projects
share, and the build-script allowlist. Both `bun.lock` files go away. CI installs with pnpm and keeps `setup-bun` for
running. No source file changes.

**Tech Stack:** pnpm 12.19.0, Node 26.13.0, Bun 1.4.4 (runtime until N8).

**Spec:** [`2026-11-12-node-migration.md`](./2026-11-12-node-migration.md), section N1, and N0(e) in
[`2026-11-12-node-migration-notes.md`](./2026-11-12-node-migration-notes.md) (spike `44d96c2`).

## Global Constraints

- Behaviour-identical port: no dependency upgrade beyond what `catalog:` unification implies, no source change.
- `pnpm-workspace.yaml` carries pnpm settings; `.npmrc` only auth/registry (none needed).
- `allowBuilds: { bun: true }` (peer of `bun-plugin-tailwind`); every other build script pnpm reports is `false`
  unless a feature needs it.
- Keep the `minimumReleaseAgeExclude` entries pnpm adds.
- CI's `bun-version` equals the `bun` version in `pnpm-lock.yaml`.
- Branch `n1-pnpm` from `node`, PR into `node`.

## Review Focus

- `pnpm install --frozen-lockfile` on a clean clone (CI): must pass with no unlisted build script.
- A phantom import in `site/` (flat `bun install` before, symlinked now): `site:build`, site tests and `og` must
  resolve every import.
- `node_modules/.bin/bun` (the peer) shadowing CI's Bun: versions must match.
- The release workflow also installs with `bun install --frozen-lockfile`: it breaks once `bun.lock` is gone.
- Root `engines.node >= 26.13`: pnpm refuses a project whose engines do not match, so CI's Node must be 26.
