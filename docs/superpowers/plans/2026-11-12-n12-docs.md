# N12 — Docs sweep: task plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every page, comment and rule tells the truth about the Node app: installed from the release tarball with
npm, run from a clone with pnpm, Node 26.13 as the only runtime; the last mention of Bun outside the history is gone,
and a test keeps it so.

**Architecture:** a Vitest test (`scripts/no-bun.test.ts`) runs `git grep` for Bun over the tracked files and fails on
any line outside an allowlist of entries `{ path, line?, reason }`; a `PENDING` list of files not swept yet keeps it
green at each commit and is empty, then removed, by the last task. The pages are rewritten task by task (code and
rules, user pages, developer pages, README and CLAUDE.md).

**Tech Stack:** Node 26.13, pnpm 12.19, npm 11 (the user's installer), Vitest, the site (MDX).

**Spec:** [`2026-11-12-node-migration.md`](./2026-11-12-node-migration.md), section N12 and "Docs policy"; the
Distribution decision (tarball + `SHA256SUMS` on a GitHub release, `npm install -g <tarball URL>`); the `llamacpp-js`
decision (its "and Bun" target claim goes away).

## Findings that shape this plan (read on this tree, 2026-11-12)

- `git grep -nIiE '\bbun\b|bun:|Bun\.'` outside `docs/superpowers/plans/**` hits about 50 files: the pages the spec
  lists, plus code comments and test names in `server/` (`sqlite.ts` 9, `proc.ts` 5, `host.ts`, `http.ts`,
  `security.ts`, `routes/web.ts`, `cli.ts`, `benchRuns.ts`, the NVML sampler, the contract suite), `site/scripts/`,
  `web/` (`tsconfig.json`, `no-node-types.ts`), `packages/` (tsconfig comments, `llamacpp-js` "Node, Bun and
  browsers"), `.gitignore`, `docs/superpowers/specs/**` (design history) and `.agents/skills/hono/SKILL.md` (vendored).
  `pnpm-lock.yaml` has none.
- `packages/webui-shared/tsconfig.json`'s comment says "Runs in Bun… Bun types for its tests": its `types` are
  `["node"]`. `server/testing/declarations.test.ts` uses `'bun'` as its sample foreign import.
- `packages/llamacpp-js/tests/package.test.ts` checks the sources for `Bun.` / `from 'bun'`: its project has Node types
  only, so `tsc -b` already refuses both.
- The release tarball's name carries the version (`llama-webui-<version>.tgz`): no `releases/latest/download/…` URL
  is stable. `dist/server/main.js` starts with `#!/usr/bin/env node`: a systemd unit needs Node on its `PATH` (a
  version manager such as fnm puts it in the login shell only).
- User pages still describe the single executable (download, `chmod +x`, "Bun runtime included", x64/arm64):
  `installation.mdx`, `requirements.mdx`, `faq.mdx`, the landing (`Hero.tsx`, `HardwareBand.tsx`, `FinalCta.tsx`);
  `configuration.mdx` already says `pnpm start` but not the installed `llama-webui`. Developer pages still describe
  `bun install`, `bun test`, `bun run compile`, `smoke-binary.ts`, `server/standalone.ts` (gone).

## Global Constraints

- No behaviour change: `server/contract/golden.json` untouched; only comments, test names, docs, rules and the landing
  copy change.
- Biome zero errors / zero warnings; `pnpm lint`, `pnpm check`, `pnpm test`, `pnpm build`, `node scripts/smoke.ts`,
  `node scripts/smoke.ts --tarball`, `pnpm site:build`, `pnpm --dir site check-links`.
- English for code, comments, tests, pages; CLAUDE.md stays in French. Site rules: front matter, `nav.ts`, URLs with a
  trailing slash, internal links without the basename.
- No screenshot retake (no UI change). Ports 7860/7861 belong to the user: manual runs on 7862,
  `http://192.168.0.20:7862`; global installs go to a prefix in the scratchpad.

## Review Focus

- A user who follows `installation.mdx` word for word on a machine with Node from a version manager: the npm global
  install, the first start, the systemd unit (Node on its `PATH`), the update and the uninstall all work.
- A contributor who follows `developers/getting-started.mdx` from a fresh clone: every command exists in
  `package.json` and does what the page says.
- An internal link or anchor a rewrite removes (`#standalone-executable`, `#serving-the-ui`…): `check-links` fails on
  it.
- A rule in CLAUDE.md that the code no longer follows, or a page section the mapping table points to that is gone.
- The guard test: an allowlisted entry that no longer matches anything (stale), or a new mention in a file nobody
  allowlisted, fails.

### Task 1: the Bun guard test

**Files:** `scripts/no-bun.test.ts` (new).

**Interface:** `ALLOW: { path: string; line?: RegExp; reason: string }[]` (`path` a prefix or exact file); `PENDING:
string[]` (exact files, swept by Tasks 2–4).

- [ ] Tests first, `scripts/no-bun.test.ts`:
  - `nothing tracked mentions Bun outside the allowlist` — `git grep -nIiE '\bbun\b|bun:|Bun\.'` (from the repo root,
    exit 1 = no match) → every `path:line:text` is covered by an `ALLOW` entry (prefix, and `line` matching the text
    when set) or by `PENDING`; the failure lists the uncovered lines.
  - `every allowlist entry still matches a line` — no stale entry.
  - Initial `ALLOW`: `docs/superpowers/` (plans and specs: the history), `.agents/skills/` (vendored), this test file.
- [ ] Run `pnpm exec vitest run scripts/no-bun.test.ts` with `PENDING` empty → Expected: FAIL listing the ~50 files.
- [ ] Fill `PENDING` with exactly those files → Expected: PASS. Commit.
