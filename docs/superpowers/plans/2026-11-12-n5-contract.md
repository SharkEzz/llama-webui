# N5 — HTTP contract suite: task plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a committed golden record of today's HTTP behaviour (status, key headers, normalised body) for every API
route, replayed over real HTTP against the real `createApp`, so N6 (Hono) and N8 (Node) must reproduce it unchanged.

**Architecture:** `server/contract/wire.ts` sends raw HTTP/1.1 bytes over `node:net` and parses the reply (the client
must not differ between Bun and Node, and fact 9 is about request framing: which headers a body-less request
carries). `server/contract/cases.ts` holds the route table, the generated case list, `normalize()` and
`runContract(baseUrl, ctx)`: pure data and runtime-neutral code that survives N6/N8 untouched.
`server/contract/contract.test.ts` boots the app (`boot()`), runs the cases, compares with `server/contract/golden.json`
or rewrites it with `UPDATE_GOLDEN=1`. `boot()` uses a new `createDeps()` (extracted from `server/index.ts`, behaviour
neutral) so the test wires the same objects as the app, with a stub monitor, an offline Hugging Face `fetch`, the fake
binaries and a temp data dir.

**Tech Stack:** Bun 1.4.4 (`bun:test`, `Bun.serve`), `node:net`, the global `WebSocket` client, `testdata/fake/`.

**Spec:** [`2026-11-12-node-migration.md`](./2026-11-12-node-migration.md), section N5 (and facts 9, 10).

## Global Constraints

- Cases over real HTTP, never `app.request()`; the golden is our own JSON (not a runner snapshot), committed, reviewed.
- Spec case list: per path every method of GET/POST/PUT/PATCH/DELETE/HEAD it lacks (405 + `Allow`) plus HEAD; bad id
  (`x`) and unknown id (`999999`); per body route malformed JSON, non-object JSON, no body with and without
  content-type, wrong content-type (415), one schema violation (message + `issues`); body-less `DELETE`/`POST` on the
  routes the web calls that way; foreign `Origin`, bad `Host`; `/api/nope`; a deep SPA URL; `/ws` without upgrade
  (426); a WebSocket connect (hello, ping → pong); an SSE stream against the fake server (headers, first event).
- Body-less requests are framed as a browser does: `POST` with `content-length: 0`, `DELETE` with neither
  `content-length` nor `transfer-encoding`.
- Recorded per case: status, `content-type`, `allow`, `cache-control`, `content-disposition` (when present), body
  (JSON parsed, else text; `none` for machine-dependent successes). Volatile values normalised: tmp dir → `<tmp>`,
  ports → `<port>`, `bootId`/`version`/`uptimeMs`/`pid` and epoch-ms timestamps → placeholders.
- Machine-dependent routes (`/api/system/info`, `/api/topology`, `/api/tuning/hardware`, `/api/tuning/checks`,
  `/api/setup`, `/api/launchpad`, `/api/bench/devices`, `/api/flags`, `/api/hf/*` successes) record status and
  headers only. No network: `HfClient` gets a `fetch` that rejects.
- `contract.test.ts` stays on `bun:test` (boots `Bun.serve`), joins `BUN_ONLY` in `vitest.config.ts`.
- `createDeps()` diff is behaviour-neutral: side effects (orphans, resume, subscriptions, signals, external watcher)
  stay in `server/index.ts`, in the same order relative to each other.
- Every divergence between `site/content/developers/api/*.mdx` and the golden is logged in the notes file's
  "Route | Docs say | Behaviour is | Resolution" table.
- `pnpm lint`, `pnpm check`, `pnpm test` green at every commit; no port 7860/7861 (the app smoke uses 7862).

## Review Focus

- A case with a side effect run before a case that reads the same entity: ids and lists in the golden depend on case
  order; the order must be fixed and the destructive body-less cases run last, on their own seeded rows.
- A schema-violation body that is accidentally valid would start a bench run, a download or llama-server: every
  violation case must answer 4xx in the golden.
- Normalisation that is too broad (a placeholder swallowing a real difference, e.g. every number) or too narrow (the
  golden differs between two runs or two machines): run the suite twice and once from a different temp dir.
- `wire.ts` parsing: chunked bodies, `content-length`, a reply with no body (204/HEAD), a closed SSE stream.
- `createDeps()` moving a DB write (`stopOrphans`) across a constructor that reads the DB.

### Task 1: Raw HTTP client

**Files:** Create `server/contract/wire.ts`, `server/contract/wire.test.ts`.

**Interfaces — Produces:** `request(base: string, r: WireRequest): Promise<WireResponse>` with
`WireRequest = { method: string; path: string; headers?: Record<string, string>; body?: string }` (adds `Host` from
`base` unless given, `Connection: close`, `Content-Length` when `body` is set) and
`WireResponse = { status: number; headers: Record<string, string> (lower-case); body: string }`;
`readSse(base, r, until: (text: string) => boolean): Promise<WireResponse>` (stops reading when `until` holds).

- [ ] **Step 1:** tests against a local `node:http` server: content-length body, chunked body, 204, HEAD, a request
      without body sends no `content-length` and no `transfer-encoding` (server sees the raw headers), a custom `Host`
      is sent as is, `readSse` returns after the first event of a never-ending stream. Expected: FAIL (no module).
- [ ] **Step 2:** implement. Expected: PASS under `pnpm test:unit` and `pnpm test:bun`.
- [ ] **Step 3:** commit `test(contract): Raw HTTP/1.1 client for the contract suite`.

`ROUTES: { path: string; sample: string; methods: Method[]; body?: { valid?: string; violation: string } }[]`,
`cases(): Case[]`, `normalize(v: unknown, ctx: NormalizeCtx): unknown`,
`runContract(base: string, ctx: NormalizeCtx): Promise<Record<string, Outcome>>` (keys are unique case names, in
run order).

- [ ] **Step 1:** `boot()`: temp dir; `openDb`; seed profile 1 (model under `<tmp>/models/`, a `writeGguf` file) and
