# N8 — Runtime flip: task plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the app runs on Node 26: `pnpm dev` (Vite middleware, one port, server hot-reloaded without killing
llama-server), `pnpm build` + `node dist/server/main.js` in production, the HTTP contract golden byte-identical, no
Bun in the app's runtime path (the site's scripts stay on Bun until N10, NVML falls back to nvidia-smi until N9).

**Architecture:** one `node:http` server per process (`server/host.ts`): `/api/*` to the Hono app through
`@hono/node-server`'s `getRequestListener`, `/ws` upgrades to the `ws` library (`noServer`) around the existing
`WsHub`, anything else to a `web` handler (Vite's middlewares in dev, an in-memory map of `dist/web` in production).
`server/dev.ts` (plain `node`, erasable TS) owns the listening socket and the Vite server, and evaluates
`server/index.ts` through the SSR module runner; every evaluation swaps its listeners onto that socket. One
`vite.config.ts` builds the client (`dist/web`) and the server (`dist/server/main.js`, dependencies bundled except
`hono`, `@hono/node-server`, `ws`).

**Tech Stack:** Node 26.13, vite 8.3.8 (client + ssr environments, module runner), `@vitejs/plugin-react` 6.3,
`@tailwindcss/vite` 4.3.5, `@hono/node-server` 2.1.x, ws 8.22, Vitest 5.1.

**Spec:** [`2026-11-12-node-migration.md`](./2026-11-12-node-migration.md), section N8 (facts 5–9, 14–15, N0(a),
N0(d)); spike code on `spike/node-port` (`server/dev.ts`, `server/spike/{host,static,main}.ts`, `vite.config.ts`,
`scripts/spike/reload-scenarios.sh`).

## Findings that shape this plan (read on this tree, 2026-11-12)

- `/ws` without an upgrade is in the golden: guarded, then `426 WebSocket upgrade expected`
  (`text/plain;charset=utf-8`), for GET and POST. The UI (`/*`) is not guarded (`GET /chat/12 (Host evil.example)`
  is a 200). `/api/*` only: Bun's `/api/*` route; `/api` alone was the UI.
- The contract boots the app with a stub `web` (`<!doctype html><title>llama-webui</title>`,
  `text/html;charset=utf-8`, `no-cache`) and `port: 0`; it reads the bound port back.
- `web`, `hostname`, `port`, `development` of `AppDeps` are read only by `createApp` (`server/app.ts`); `AppDeps`
  is imported by `api.ts`, `deps.ts`, `index.ts`, the contract.
- `createDeps()` is constructors only (the placement tracker subscribes to the logs and the supervisor; the hub
  starts its ping timer); everything that touches rows or starts work is in `server/index.ts` after it.
- The only runtime reads of `import.meta` paths: `buildWebRoutes(import.meta.dirname/../web/index.html)` (goes) and
  the NVML `workerUrl()` (`./worker.ts` next to the module; `new Worker` is not a global on Node → the monitor
  resolves `null` → nvidia-smi, as the plan says until N9).
- `guard()` tests in `server/security.test.ts` build `Request`s with a string body and no `content-length` header (an
  in-memory `Request` never has one).

## Global Constraints

- Golden byte-identical (`pnpm exec vitest run server/contract` without `UPDATE_GOLDEN`) at every commit that
  touches the HTTP path; a difference on Node is fixed in `host.ts`/`security.ts`, never in the golden.
- Behaviour-identical port: same CLI, same routes, same WebSocket messages, same cache headers, same 503 page when the
  UI is missing. Anything worth improving goes to the notes file.
- `server/dev.ts`, `scripts/smoke.ts`: erasable TS run by plain `node`, imports `vite` and `node:*` only (`dev.ts`)
  or `node:*` only (`smoke.ts`).
- Survivors of a dev reload unchanged (supervisor, log ring, monitor, bench gate, placement, download handover) plus
  the dev host (`__llamaWebuiDevHost`: the `http.Server` and Vite's middlewares).
- Dependencies: `vite`, `@tailwindcss/vite` through `catalog:`; `@hono/node-server`, `ws` in `server/package.json`
  `dependencies`; `@types/ws` in its `devDependencies`; `@vitejs/plugin-react`, `vite`, `@tailwindcss/vite` in the
  root `devDependencies`. Removed: `bun-plugin-tailwind`, `bunfig.toml`, `allowBuilds.bun`. `@types/bun` stays until
  N9 (server and scripts still list `types: ["bun"]`).
- Ports: 7860/7861 are the user's; manual runs on 7862 with a copy of the database.

## Review Focus

- A body-less write (`POST`/`DELETE` with no content-type, as `hc` sends them) through Node's HTTP stack: passes the
  guard; a non-JSON body with a `content-length` or `transfer-encoding`: 415.
- A malformed `Host` (`a b`), a foreign `Origin` on the `/ws` upgrade, an upgrade on another path (prod: destroyed;
  dev: left to Vite's HMR listener): same answers as on Bun.
- A dev reload that throws at run time after the new instance was built: the old instance keeps serving (it is
  disposed only once the new one has mounted); a failed reload followed by a fix re-imports the entry once.
- Production web: a deep URL (`/chat/12`), `/index.html` itself, an asset path that does not exist (→ the app, not a
  404), HEAD; `dist/web` missing → 503 text, API still served.
- The server bundle imports only `node:*`, `hono`, `@hono/node-server`, `ws` (and their subpaths); nothing reads the
  source tree at run time (`import.meta.dirname` in a bundled chunk is `dist/server`).

### Task 2: Node host and WebSocket adapter

**Files:** Create `server/host.ts`, `server/ws/attach.ts`, `server/host.test.ts`. Modify `server/package.json`
(`@hono/node-server`, `ws`, `@types/ws`), `pnpm-lock.yaml`.

**Interfaces:**

- Produces `type WebHandler = (req: IncomingMessage, res: ServerResponse) => void`.
- Produces `mount(o: { server: Server; fetch: (req: Request) => Response | Promise<Response>; hub: WsHub;
  web: WebHandler; hostname: string; port: number; dev: boolean }): Promise<number>` — swaps this call's `request` /
  `upgrade` listeners onto `server` (removing the ones a previous `mount` on the same server put there), listens on
  the first call only, resolves the bound port (rejects on a listen error).
- Produces `attachSocket(hub: WsHub, ws: WebSocket): void` (`server/ws/attach.ts`): attach, text messages to
  `hub.receive`, detach on close, errors swallowed.

Routing: `pathname` starts with `/api/` → the API listener (`getRequestListener(fetch, { overrideGlobalObjects:
false })`); `/ws` (no upgrade) → `guard()` then `426 WebSocket upgrade expected` `text/plain;charset=utf-8`; anything
else → `web`. Upgrade: `/ws` → `guard()` on a `Request` built from the incoming headers (`http://<host><url>`); refused
→ the guard's status line, headers and JSON body written to the socket, then closed; accepted →
`wss.handleUpgrade` → `attachSocket`. Another path: destroyed in production, ignored in dev (Vite's HMR listener).

- [ ] **Step 1: Failing tests** (`server/host.test.ts`, a real `createServer()` on port 0, a `WsHub`, a stub web
      handler, `createApi`-free: a tiny Hono app with the real `guardMw`): `/api/x` reaches the app; `/chat/12` reaches
      `web`; `GET /ws` → 426 with that body and type; `GET /ws` with `Host: evil.example` → 403 `Host not allowed`; a
      WebSocket on `/ws` gets the hub's `hello`, and `ping` → `pong`; a WebSocket with `Origin: http://evil.example` is
      refused (403, no `hello`); an upgrade on `/other` is destroyed when `dev: false`; a second `mount()` on the same
      server replaces the listeners (one `request` listener, the new app answers) and does not listen again; a body-less

- [ ] **Step 2: Run** `pnpm exec vitest run server/host.test.ts` — Expected: FAIL (no module).
