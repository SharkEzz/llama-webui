# J1 — Socle llama-webui : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un monorepo Bun qui démarre en une commande, avec une API Bun (health, WebSocket, sqlite + settings) et une UI Vite/React/Tailwind/shadcn au design verre sombre et fond animé, navigation complète avec pages vides.

**Architecture:** Trois workspaces : `shared/` (types et schémas zod consommés des deux côtés), `server/` (Bun.serve : REST `/api/*`, WS `/ws`, sqlite, service de `web/dist` en prod), `web/` (Vite + React 19, react-router, zustand pour l'état WS). En dev Vite proxie `/api` et `/ws` vers Bun.

**Tech Stack:** Bun 1.4.4, TypeScript 7, zod 4, bun:sqlite ; Vite 8, React 19, @vitejs/plugin-react 6, Tailwind 4 (`@tailwindcss/vite`), shadcn 4 (base radix), react-router 8, zustand 5, lucide-react, @fontsource-variable/inter, @fontsource-variable/jetbrains-mono.

**Spec:** `docs/superpowers/specs/2026-11-05-llama-webui-design.md`

## Global Constraints

- UI en français, thème sombre uniquement.
- Ports : serveur Bun **7860**, Vite dev **5173**.
- Frontend Vite (décision explicite ; amender `CLAUDE.md`).
- Tests minimaux : un seul test unitaire en J1 (dépôt settings). Tout le reste se vérifie à la main.
- Données locales dans `$XDG_DATA_HOME/llama-webui/` (défaut `~/.local/share/llama-webui/`), surchargeable par `LLAMA_WEBUI_DATA_DIR`. Fichier `llama-webui.sqlite`.
- Fond : 4 bulles radiales (violet, cyan, ambre, rose) floutées `blur(80px)`, animations 40–90 s, `prefers-reduced-motion` respecté.
- Cartes verre : `backdrop-filter: blur(16px)`, fond `white/5`, bordure `white/10`.
- Commits fréquents, messages en français, suffixe `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

### Task 2 : Serveur Bun — health, WebSocket, sqlite, settings, statique

**Files:**
- Create: `server/index.ts`, `server/app.ts`, `server/ws/hub.ts`, `server/db/open.ts`, `server/db/migrations.ts`, `server/db/settings.ts`, `server/static.ts`, `server/paths.ts`
- Test: `server/db/settings.test.ts`

**Interfaces:**
- `paths.ts` : `export function dataDir(): string` (règle des Global Constraints, crée le dossier avec `mkdirSync({recursive:true})`), `export function dbPath(): string`.
- `db/open.ts` : `export function openDb(path: string): Database` (bun:sqlite, `PRAGMA journal_mode=WAL; foreign_keys=ON`) puis applique `runMigrations(db)`.
- `db/migrations.ts` : `export function runMigrations(db: Database): void` — table `schema_version(version INTEGER)` ; migration 1 : `CREATE TABLE settings(key TEXT PRIMARY KEY, value_json TEXT NOT NULL)`. Les migrations suivantes (J2+) s'ajoutent au tableau `MIGRATIONS: string[]`.
- `db/settings.ts` : `export class SettingsRepo { constructor(db: Database); get(): Settings; patch(partial: Partial<Settings>): Settings }` — `get()` fusionne `DEFAULT_SETTINGS` avec les lignes stockées puis valide via `SettingsSchema.parse` ; `patch()` valide puis `INSERT OR REPLACE` clé par clé.
- `ws/hub.ts` : `export class WsHub { attach(ws: ServerWebSocket<unknown>): void; detach(ws): void; broadcast(msg: WsMessage): void; size(): number }` — ping toutes les 15 s, ferme un client sans `pong` après 2 pings manqués.
- `static.ts` : `export function serveStatic(req: Request, distDir: string): Response | undefined` — fichier existant → `Bun.file`, sinon `index.html` (fallback SPA) ; si `index.html` absent → `Response` texte 503 « Build web absent : lancez bun run build ».
- `app.ts` : `export function createApp(deps: { db: Database; hub: WsHub; settings: SettingsRepo; distDir: string; port: number })` retourne `Bun.serve({...})` avec routes `GET /api/health` → `{ ok: true, version: string, uptimeMs: number }`, `GET /api/settings` → `Settings`, `PATCH /api/settings` (body JSON partiel) → `Settings`, `GET /ws` → upgrade WS (hub envoie `hello` à l'ouverture), fallback → `serveStatic`.
- `index.ts` : compose tout, `distDir = path.resolve(import.meta.dir, "../web/dist")`, port 7860, log d'une ligne « llama-webui sur http://127.0.0.1:7860 ».
