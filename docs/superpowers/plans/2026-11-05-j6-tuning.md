# J6 — Tuning et sweep : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.


**Goal:** Une page Tuning qui, pour un modèle et un préréglage, recommande une configuration expliquée flag par flag (estimateur étendu à Vulkan3, `-ot`, `-ncmoe`, débordement RAM/NVMe), laisse définir un espace de recherche, l'exécute en sweep llama-bench persistant (serveur arrêté une fois, N runs, relancé une fois), classe les résultats en montrant le bruit de mesure, valide les meilleurs par de vrais runs serveur et en fait un profil ; plus un panneau de vérifications système sur la page Système, et des routes React chargées à la demande.

**Architecture:** La « garde du serveur » (arrêt du serveur géré, pause du détecteur de serveur externe, relance) sort de `BenchRunner` dans un `BenchGate` qui vit dans le runtime (survit à `bun --hot`). L'exécution d'un run (llama-bench ou serveur) devient un `RunExecutor` réutilisé tel quel par les runs ponctuels et par les sweeps. Un sweep = une ligne `sweeps` + ses éléments créés d'avance dans `bench_runs` au statut `queued` (`sweep_id`, étiquette, verdict de l'estimateur) : la file est la base, donc la reprise après arrêt est naturelle. L'estimateur est réécrit autour d'un module de **placement** qui, pour des `BenchParams` donnés (`-ngl -dev -ts -sm -ncmoe -ot`), répartit chaque tenseur du GGUF entre devices et RAM ; la recherche par préréglage et le filtre de l'espace en découlent. Logique pure dans `shared/` (espace, étiquettes, classement, bruit), estimation et checks côté serveur (ils lisent le GGUF et `/sys`).

**Tech Stack:** existant J5. Aucune nouvelle dépendance. React Router 8.5 (`lazy` par route). shadcn déjà installés (collapsible, tabs, table, progress, checkbox, badge, tooltip, select, slider).

**Spec:** `docs/superpowers/specs/2026-11-05-llama-webui-design.md` (J6, modèle de données `sweeps` / `bench_runs.sweep_id`, Transport `sweep-progress`). Plan J5 : `docs/superpowers/plans/2026-11-05-j5-benchmark.md`. ## Review Focus

1. **Le serveur arrêté pour un sweep revient toujours, une seule fois** : sweep réussi, OOM sur plusieurs éléments, annulation pendant l'arrêt du serveur, pendant un chargement, entre deux éléments, rechargement `bun --hot` au milieu (le nouveau module reprend, le serveur n'est pas relancé entre-temps), arrêt complet. Tests runner Task 3 (« a sweep stops the server once and restarts it once », « a reload hands the held gate to the next runner »), vérif Task 9.
2. **Espaces vides ou absurdes** : espace sans aucune dimension (1 élément = la base), `-ts` dont la longueur ne correspond à aucun jeu de devices (ignoré avec un message), toutes les combinaisons exclues par l'estimateur (le bouton « Lancer » est désactivé et le compte dit pourquoi), 500 combinaisons (avertissement de durée, pas de blocage). Tests `expandSpace` Task 1, vérif Task 8.
3. **Estimateur et réalité** : un verdict `fits` qui finit en OOM n'invalide rien (le run est `failed`, le classement l'affiche à côté de son verdict) ; un modèle plus gros que VRAM + RAM donne `ramOverflowBytes > 0` et un débit disque nécessaire, pas une exception ; un GGUF sans tenseurs experts avec `-ncmoe` → avertissement « modèle dense : -ncmoe sans effet ». Tests `placement`/`estimate` Task 2.
4. **Classement trompeur** : deux configs à 3 % de tg d'écart ne doivent pas apparaître comme départagées (ex æquo), un run `failed`/`cancelled` n'a pas de rang, un sweep sans aucun run `ok` n'a pas de meilleur (`bestRunId null`, bouton « Valider » désactivé), la validation serveur ne se mélange pas à l'exploration (deux tableaux, badge d'outil). Tests `rankRuns` Task 1, vérif Task 8.
5. **Suppressions et ids** : supprimer un sweep supprime ses runs (cascade) et le diffuse ; supprimer le meilleur run d'un sweep met `best_run_id` à NULL ; après la migration, créer puis supprimer le dernier run puis en créer un autre donne un id **strictement supérieur** (plus de réutilisation). Test migration Task 3.
