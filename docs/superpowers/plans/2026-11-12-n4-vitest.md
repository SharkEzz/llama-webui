# N4 — Vitest + `tsc -b`: task plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the unit tests run on Node under Vitest 5.1, llamacpp-js's tests under `node --test` only, and the type
check is `tsc -b`; only the files that boot `Bun.serve`/`Bun.build` stay on `bun test`. The app still runs on Bun.

**Architecture:** one root `vitest.config.ts` with four projects (server + scripts, shared, web with its `@` alias,
site with its own), `environment: 'node'`, explicit imports, top-level `oxc: { target: 'esnext' }`. `pnpm test` runs
Vitest, then llamacpp-js, then the Bun-only files, so nothing is forgotten.

**Tech Stack:** Vitest 5.1.0, Node 26.13.0, TypeScript 7.0.2 (`tsc`), Bun 1.4.4 (app, Bun-only tests), Rolldown 1.2.18
(already installed by Vite).

**Spec:** [`2026-11-12-node-migration.md`](./2026-11-12-node-migration.md), section N4.

## Global Constraints

- Measured on the branch before planning: with `bun:test` → `vitest` in the 64 files, 62 files pass on Node at once;
  the failures are the four un-awaited `.rejects` of `server/models/gguf.test.ts` (fact 13) and `workerUrl(true)` in
  `server/collectors/nvml/monitor.test.ts` (reads `Bun.main`). `tsc -b` on the real tree: clean, ~1 s, no
  TS4023/TS2742 (the declared risk does not materialise). The site's `tsc -p site` is clean too.
- Bun-only list (exact): `server/routes/routes.test.ts` (`Bun.serve`), `server/routes/web.test.ts` (`Bun.build`).
- Assertions are not weakened: a test that cannot run on Node either stubs the Bun global it reads or stays on Bun.
- Behaviour-identical: no app code changes in this milestone.
- `pnpm lint`, `pnpm check`, `pnpm test` green at every commit.

## Review Focus

- Vitest `exclude` replaces the default list: it must keep `configDefaults.exclude` (else `node_modules` tests run).
- `clearMocks` defaults to `true` in Vitest 5: a test reading mock calls across `beforeEach` would silently change.
- A test that passed on Bun only because an assertion was never awaited (fact 13): every `.resolves`/`.rejects` must
  be awaited.
- `using` must stay native (`oxc.target`) in every project, not only the root.
- The bundling checks of llamacpp-js must still assert what they did with Bun's bundler (tree-shaking, no Node
  built-ins in the browser modules), and skip, not fail, where no install exists (the Node 24 CI job).
