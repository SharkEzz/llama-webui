# Plan — llama-webui website (landing + user docs + developer docs)

## Context

llama-webui has a rich README but no public site. The README's "For developers" section even says _"Full
documentation will live on a dedicated site."_ Goal: a static website, hosted on **GitHub Pages** at
`https://sharkezz.github.io/llama-webui/`, with:

1. a **landing page** with a polished, modern, "tech premium" look (Linear / Vercel / Raycast family) that presents the
   app's main features;
2. a **user documentation** (install, first run, every page of the app, task-oriented guides);
3. a **developer documentation** (architecture, server modules, frontend, hand-written REST + WebSocket reference,
   contributing).

Primary call to action: **"Get started"** → install doc. GitHub is secondary. Success = a visitor understands in
10 seconds what llama-webui does and why, and can install and use it, or contribute, using only the site.

### My calls (the user can override them)

- **Routing and static output:** React Router 8 in **framework mode** (Vite plugin `@react-router/dev`) with
  `ssr: false` and `prerender` covering all routes. Every page (Home, each doc page) gets real HTML: SEO,
  no-JS fallback, a Pagefind index, and no SPA-fallback hack on GitHub Pages.
- **Visual identity:** same identity as the app. Palette from the logo and the `--tone-*` tokens (blue
  `#3698ff` / `oklch(0.68 0.19 255)`, teal `#44d0c1`, amber `#fcb442`, rose), Inter Variable + JetBrains
  Mono Variable (`@fontsource-variable/*`), radius 1rem, "glass" surfaces. The landing pushes it further: near-black
  background, 1px grid, blurred halos, gradient text for the tagline.
- **Animation:** the `motion` package. Fade/slide reveals on scroll, light parallax, no scroll-jacking. Everything
  freezes under `prefers-reduced-motion`.
- **No three.js** on the site (bundle weight). The topology appears as a real screenshot with an animated CSS/SVG
  overlay (particles on the links).
- **Code sharing:** the site does **not** import code from `web/`. Gauge, StatTile, glass and tokens are copied and
  adapted (a comment names their origin). This keeps `site/` decoupled from the Bun toolchain.
- **Charts in the hero:** a lightweight custom SVG chart instead of uPlot, styled like `TimeSeriesChart`
  (2px lines, 10% fill, mono axes).
- **Brand logos (NVIDIA, AMD…):** shown as text badges plus lucide icons, not official logos (trademarks).
- **Mermaid:** the architecture diagram is a React/SVG component in the site's style. No Mermaid runtime.
- **URLs:** trailing-slash form everywhere (`/llama-webui/docs/installation/`). Prerender writes `…/index.html`
  and Pages redirects to the slash form, so canonical tags, the sitemap, Pagefind URLs, the link checker and MDX links
  all use the slash form.
- **Screenshots:** a repeatable **headless capture script** using the local `/usr/bin/chromium` (`puppeteer-core`)
  rather than the Chrome extension, which runs on another machine and returns images, not files. The extension
  stays the tool for visual reviews.

```
  content/
    docs/**.mdx           # user docs

    root.tsx              # <html>, no-flash theme script, fonts, meta

```

## Milestones and sub-tasks

> Each milestone ends with: `bun run lint`, `bun run check` and `bun test` green (with the site included), plus
> `cd site && bun run build` OK, then a commit (and a PR per milestone, unless the user says otherwise). Content
> tasks start by reading the cited source files: the docs must describe what the code does, not the README.

### M1 — Scaffold and deployment pipeline

- **1.1** Scaffold `site/`:
  - Vite 8, React 19, React Router 8 framework mode (`@react-router/dev`), `@tailwindcss/vite` 4.3, TypeScript;
  - `bun install` inside `site/`;
  - `base`/`basename` set to `/llama-webui/`.
  - **Early spike (go/no-go):** check that MDX files work as route modules with `prerender` and the basename.
    `@mdx-js/rollup` must run before `reactRouter()` (`enforce: 'pre'`), because the React Router plugin parses route
    files with Babel. Also check where `+types` land for route files under `content/`, outside `src/`.
    - **Fallback:** a `docs/*` splat route. The MDX module is resolved through `import.meta.glob` and loaded in a
      `clientLoader` + `loader` (prerender) **before** render, which avoids hydration mismatch and content flash.
      The path list comes from `content/` (via `Bun.Glob` / `fs`) inside `react-router.config.ts`.
- **1.2** shadcn init (style `base-nova`, Base UI, lucide, aliases `@/`; the `shadcn` package is a runtime
  dependency because the CSS imports `shadcn/tailwind.css`), plus the base components: button, badge,
  card, tabs, dialog, command (cmdk), scroll-area, separator, tooltip, dropdown-menu, sheet (mobile nav).
- **1.3** Design tokens in `src/styles/app.css`:
  - port the light/dark tokens from `web/src/index.css`, with the `.dark` custom variant, `--tone-*`,
    `--surface*`, radius and the `num` utility;
  - add the landing tokens: `--bg-deep`, 1px grid (mask radial), glow utilities, gradient text;
  - fonts via `@fontsource-variable/inter` and `@fontsource-variable/jetbrains-mono`.
- **1.4** Theme:
  - inline script in `root.tsx` that applies `.dark` before paint (localStorage, default **dark**);
  - `ThemeToggle` (System / Light / Dark);
  - `ThemedImage` (dark and light versions, swapped by class).
- **1.5** Shell:
  - `SiteHeader` (logo SVG adapted from `docs/assets/logo-*.svg` / `web/src/favicon.svg`, links Docs,
    Developers, GitHub, ⌘K search, theme; sticky glass with blur; mobile Sheet);
  - `SiteFooter`;
  - 404: a catch-all `*` route rendering "Page not found". GitHub Pages' `404.html` is a copy of
    `__spa-fallback.html` (generated by React Router when `/` is prerendered), **not** a page prerendered for another
    URL, which would break hydration;
  - per-page `meta` (title, description, OG).
- **1.6** Quality integration:
  - `biome.json`: ignore `site/src/components/ui/**`, `site/build`, `site/.react-router`.
  - **Check `.mdx` handling:** Biome 2.6 already formats Markdown, and `ignoreUnknown` is `false`. Run
    `biome check site/content` on a sample page. If Biome rewrites the JSX/imports of an MDX file or reports errors,
    exclude `site/content/**/*.mdx` from `files.includes`: this is a file outside Biome's scope, not a disabled rule.
  - Type check: `site/package.json` gets `typecheck` = `react-router typegen && tsc --noEmit` (the `+types` only
    exist after typegen). The root `check` script runs it after the existing checks: `… && bun run --cwd site
    typecheck`. Verify that it works on a clean checkout, and that `bun check` does not pick up a script of the same
    name instead.
  - Tests: root `test` = `bun test server shared site`. Only pure modules are tested (`telemetry.ts`, nav, utilities),
    with no import of `.mdx`, CSS, `import.meta.glob` or `virtual:`. `nav.test.ts` lists files with `Bun.Glob`.
    Verify that the `@/` alias resolves from the root, or use relative imports in the tested modules.
  - root helper scripts `site:dev`, `site:build` and `site:preview`, plus `site/.gitignore` (`build/`,
    `.react-router/`, `node_modules/`).
- **1.7** GitHub Actions:
  - `.github/workflows/site-ci.yml` runs on `pull_request` and push. It uses `oven-sh/setup-bun` and
    `bun install --frozen-lockfile` (root + `site/`), then `bun run lint`, `bun run check`, `bun test`, the site build
    and (from M5 on) `check-links`.
  - `.github/workflows/site-deploy.yml`:
    - build, then `actions/upload-pages-artifact` (`site/build/client`) → `actions/deploy-pages`;
    - **`workflow_dispatch` only until M8** (site held back), then push to `master` is added at M8;
    - permissions `pages: write`, `id-token: write`, concurrency group `pages`.
  - **User action (in M8):** enable Pages → "GitHub Actions" source in the repo settings.
- **1.8** `scripts/postbuild.ts`: `404.html` (copy of `__spa-fallback.html`) and `sitemap.xml` (slash URLs).
  Pagefind is added in M5. No `robots.txt`, because crawlers only read the one at the host root. No `.nojekyll`
  either, as `deploy-pages` does not need it. Validate locally with `bun run preview`; there is no public deploy
  before M8.

### M3 — Landing: hero and live dashboard

- **3.1** `landing/telemetry.ts`: pure, deterministic simulation (seeded) of a realistic loop:
  - idle → prompt burst (~1500–3000 tok/s pp) → generation (~45–120 tok/s tg with jitter, MTP acceptance ~70%)
    → idle;
  - VRAM of 2 GPUs (e.g. RTX 4090 + RX 7900 XTX: CUDA + Vulkan, which shows off mixed hardware), CPU/RAM, context
    filling slot by slot.
  - Its shape mirrors `Snapshot` from `shared/src/monitor.ts` (`rates`, `kv`, `spec`, `slots`, `gpus`, `system`).
    `telemetry.test.ts` covers bounds and the phase sequence.
- **3.2** `LiveDashboard.tsx`: a faithful replica of `web/src/features/dashboard/DashboardPage.tsx`, built from:
  - the 4 StatTiles (Generation blue, Prompt teal, Speculative amber, Context rose);
  - `SystemStrip` gauges (CPU, RAM, VRAM ×2), the 270° SVG `Gauge` ported from `components/glass/Gauge.tsx`;
  - Throughput SVG chart, slots card, and a 3–4 row "Recent requests" table that fills in over time.
  - Container: browser/glass window frame with a fake sidebar, a halo behind it, and a slight 3D tilt that
    straightens on scroll.
  - `requestAnimationFrame` loop paused when the hero is off screen (IntersectionObserver) and under reduced
    motion (static frame).
  - Responsive: on mobile, tiles + chart only.
- **3.3** `Hero.tsx`:
  - small badge above the title ("Open source · MIT · Linux");
  - the tagline in large type with a gradient on "control room";
  - the README subtitle;
  - CTA **Get started** (primary → `/docs/getting-started/installation`) and **GitHub** (secondary, with a
    "Star" icon);
  - grid + halos background in logo colors.
- **3.4 Visual checkpoint with the user:** screenshots of the hero (dark/light, desktop/mobile) via Chrome at
  `http://192.168.0.20:5173/llama-webui/`. The site's `dev` script listens on `0.0.0.0`, because the browser runs on
  another machine. Iterate before building the sections.
