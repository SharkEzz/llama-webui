**Goal:** Answer the six N0 questions of the migration plan with measurements, and record them in the "Spike
findings" table of the notes file, before N1 starts.

## Global Constraints

- Time box: 3 days. An item still open at the end is recorded as "inconclusive" with what was tried.
- Spike code is never merged; it may cut corners (no lint, no tests beyond the item's own probe), but every
  measurement must be reproducible from a command written in the findings.
- No change on `node` other than this plan and the notes file. No push, no PR without asking the user.
- If (a) or (c) fails even with its fallback: stop and go back to the user before N1.
- Versions pinned as in the spec: `hono@~4.13.18`, `@hono/node-server@^2.1.7`, `@hono/zod-validator@^0.9.1`,
  `ws@^8.22.2`, `vite@^8.3.8`, `vitest@^5.1.0`, `@vitejs/plugin-react@^6.3.0`, `@tailwindcss/vite@^4.3.5`.
- URLs given to the user or used in the browser: `http://192.168.0.20:<port>`, never localhost. The spike dev server
  listens on `0.0.0.0:7870` (7860 is the everyday instance, 7861 the demo one).
- Real GPUs are used by (b) only for NVML reads (no model loaded): no need to ask the user to free them.

## Review Focus

1. A reload that re-runs `index.ts` but keeps the **old** `request`/`upgrade` listeners (double handling, or requests
   served by stale code): the probe returns `evalCount` from the handler, so a stale listener shows an old count.
2. A reload while a `/ws` client is connected: the old hub must close it and the new one must greet it with the same
   `bootId`; a socket left attached to the disposed hub would never get `hello` again.
3. A syntax error in a server file followed by its fix: the runner must recover without a manual restart.
4. Ctrl-C during a reload, or with the fake server still loading: llama-server must not be orphaned (`kill -0 <pid>`
   fails after exit).
5. The prod bundle booted outside the repo silently resolving a dependency from the repo's `node_modules` (a false
   pass for (d)): boot it from `/tmp/claude-1000/…/scratchpad/n0-boot` with `NODE_PATH` unset.

Each is covered by a check in Task 4 or Task 7.

- Create `scripts/spike/ws-probe.ts`: Node 26 global `WebSocket` client to `ws://192.168.0.20:7870/ws`, logs every
  `hello` `bootId` with a timestamp and reconnects 500 ms after a close.
- Modify `packages/webui-shared/src/index.ts`: add `export const SPIKE_MARK = 'a';` (read by `server/routes/spike.ts`
  and logged by `web/src/main.tsx` with `console.info('[spike]', SPIKE_MARK)`).

**Interfaces:**

  `mount(...)`; increments `globalThis.__spikeEvalCount`; logs `[spike] eval #<n> at <performance.now()>`; on first

  `[<repo>/testdata/fake/fake-llama-server, '--port', '18080']`, `host: '127.0.0.1'`, `port: 18080`,
  `profileId: 1`. Its dispose hook: `hub.dispose()`.
- `spikeRoutes(deps: { runtime: Runtime; evalCount: number })` returns
  `new Hono().get('/api/spike/state', (c) => c.json({ pid, bootId, evalCount, mark: SPIKE_MARK, state }))`.

  `getRequestListener(app.fetch)`, else `web`) and `upgrade` (`/ws` → `WebSocketServer({ noServer: true })` →
  hub attach/receive/detach; any other path left to Vite), `listen(7870, '0.0.0.0')` only if not listening.
