# N6 — Hono + `@hono/zod-validator`, still served by `Bun.serve`: task plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every `/api/*` route answered by one chained Hono app (`createApi`), validators on the inputs, with the
N5 golden byte-identical (one approved exception: `Host: a b`), still on Bun.

**Architecture:** `server/api.ts` builds `new Hono<Env>()` with `guardMw`, `jsonCharset`, `allow.mw`, then one
`.route('/', xRoutes(deps))` per domain file. `Bun.serve` keeps `{ ...legacy, '/api/*': (req, server) => api.fetch(req,
{ server }), '/ws': …, ...deps.web }` while files move one at a time (Bun's precedence sends a legacy path to its old
handler), then `legacy` disappears. Helpers live in `server/http.ts`: `id(what)` (param validator), `json(check)`
(JSON body validator keeping today's order of errors), `object(body)`, the allow table, the guard middleware.

**Tech Stack:** hono 4.13.18 (catalog `~4.13.18`), `@hono/zod-validator` 0.9.1, zod 4, Bun 1.4.4 `Bun.serve`.

**Spec:** [`2026-11-12-node-migration.md`](./2026-11-12-node-migration.md), section N6 (facts 9–12).

## Global Constraints

- Golden byte-identical after every task: `bun test ./server/contract` green **without** `UPDATE_GOLDEN`. Only Task 6
  regenerates it, and its diff is exactly the new `Host: a b` case (user-approved contract change, 2026-11-12).
- A route file moves to Hono **whole** (a migrated static path behind a legacy `:param` route would be caught by it).
- Static paths registered before the `:param` path they would shadow (fact 10), checked by an invariant test.
- Each route keeps today's order of checks: `id()` (format only) → body → lookups/409s, except where the handler does
  a lookup or a 409 before reading the body today (`POST /api/sweeps/:id/resume`, and any other found): there the body
  stays read inside the handler, with `object(await c.req.json())`.
- Messages unchanged: `Invalid JSON`, `JSON object expected`, `Invalid data: … (path)` + `issues`, the imperative
  messages (`content: expected a string`, `profileId: …`, `?failed=1 expected`). `errorResponse` kept verbatim plus one
  branch: Hono's `HTTPException` 400 `Malformed JSON in request body` → `{ error: 'Invalid JSON' }`.
- JSON replies keep `content-type: application/json;charset=utf-8` (Bun's `Response.json`; Hono's `c.json` sends
  `application/json`, and Node's `Response.json` will too in N8): one `jsonCharset` middleware rewrites exactly
  `application/json` to that.
- Query strings are read as today (`new URL(c.req.url).searchParams`), not `c.req.query()` (different decoding).
- `req.signal` → `c.req.raw.signal`; `server.timeout(req, 0)` → `c.env.server?.timeout(c.req.raw, 0)` (shim, N8 drops it).
- No behaviour change beyond Task 6; candidates go to the notes backlog. `pnpm lint`, `pnpm check`, `pnpm test` green
  at every commit; ports 7860/7861 never used (app smoke on 7862).

## Review Focus

- A validator moved ahead of a lookup or a 409 the handler did before reading the body: a request that is both wrong
  and conflicting changes answer, with no golden case to see it.
- `HEAD`: Hono runs GET handlers for HEAD; the allow table must treat HEAD as GET (405 on a path without GET, with the
  path's `Allow`).
- `jsonCharset` touching a reply it must not (SSE `text/event-stream`, 204, the 405 body, errors from `onError`).
- Static-before-param order inside one file, and the allow table's choice of the most specific pattern
  (`/api/bench/runs` vs `/api/bench/:id`, `/api/profiles/import/llama-tui` vs `/api/profiles/:id/duplicate`).
- Classes across `bun --hot` reloads: errors are matched by `name` (`isHttpError`) or by Hono's own class, never by
  a class from a module the hot reload does not refresh.

### Task 1: Foundation (N6a): deps, helpers, `createApi`, health + settings

**Files:** `pnpm-workspace.yaml`, `server/package.json`, `pnpm-lock.yaml`; create `server/api.ts`, `server/http.test.ts`;
modify `server/http.ts`, `server/app.ts`, `server/routes/settings.ts`, `server/contract/contract.test.ts`.

**Interfaces — Produces:**

- `type Env = { Bindings: { server?: Server<undefined> } }` (`server/http.ts`).
- `guardMw`: `guard(c.req.raw)` or `next()`. `jsonCharset`: after `next()`, `application/json` → `application/json;charset=utf-8`.
- `allowTable(): { mw: MiddlewareHandler; load(routes: { method: string; path: string }[]): void }`: for the most
  specific registered pattern matching the path (fewest `:param` segments, then registration order), a method (HEAD
  counted as GET) it lacks → 405 `{ error: 'Method not allowed (<Allow>)' }`, `Allow` in `GET, POST, PUT, PATCH,
  DELETE` order; no matching pattern → `next()` (→ `Unknown route`).
- `id(what)`: `validator('param')` → `{ id: number }`, else `notFound(what)`.
- `json<T>(check: (body: unknown) => T)`: `validator('json')`; content-type not JSON → `HttpError(400, 'Invalid JSON')`,
  else `check(value)`. `object(body): Record<string, unknown>` throws `JSON object expected`.
- `createApi(deps: AppDeps)` (`server/api.ts`) and `type AppType`; `apiRoutes(api)`: `{ method, path }[]` without
  middleware entries.
