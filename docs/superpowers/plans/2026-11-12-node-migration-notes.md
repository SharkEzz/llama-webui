## Findings during the port

- (N3) Bun 1.4.4's `node:sqlite` exports `DatabaseSync` but not `Database`, and `@types/node` 26.6 declares only
  `DatabaseSync`: `server/db/sqlite.ts` wraps `DatabaseSync` (Node 26.13 prints no deprecation warning for it). Bun's
  `node:sqlite` also refuses `true`/`false`/`undefined` bindings (`ERR_INVALID_ARG_TYPE`), which Node ≥ 26.10 accepts;
  the wrapper maps them to `1`/`0`/`NULL`, as `bun:sqlite` did. `readOnly` is camelCase: an unknown `readonly` key is
  silently ignored. `node:sqlite` binds missing values as `NULL` where `bun:sqlite` threw: the wrapper counts the `?`
  placeholders and throws the same message. A read of every repository on a copy of the real database gave the same
  JSON through `bun:sqlite` and through the wrapper.
- (N4) Tests run on Node (Vitest), but the app runs on Bun until N8 and the runtimes differ: `test:bun` replays the
  server, scripts, shared and llamacpp-js tests under `bun test` (Bun's runner answers `vitest` imports and implements
  `node:test`); removing the wrapper's boolean shim fails there and passes under Vitest. Bun's `vi` has no
  `unstubAllGlobals`, so a test that must run on both stubs a global by hand. Bun-only (Bun.serve/Bun.build):
  `server/routes/routes.test.ts` (on Vitest since N6, through `app.request`), `server/routes/web.test.ts`. `tsc -b` on the real tree: clean, no TS2742/TS4023.
  N8: shrink `test:bun` to nothing (drop the script) once Bun no longer runs the app.
- (N5) Pre-existing bug, kept (no behaviour change in N5): a `Host` that is not a valid authority (`Host: a b`) makes
  Bun hand the handler a relative `req.url`, so `new URL(req.url)` in `guard()` (`server/security.ts`) throws outside
  the `try` of `guarded()` and Bun answers its own 500 instead of 403 `Invalid host`. Not in the golden (runtime
  specific). Fixed in N6 (user-approved contract change): `guard()` parses `req.url` inside its `try` and answers
  403 `Invalid host`; the case `GET /api/health (Host a b)` is in the golden. Bun's `os.homedir()` ignores a `HOME` changed at
  run time (Node follows it): the contract normalises the home directory to `<home>`. The contract records only the
  top-level field names of machine-dependent successes (`/api/system/info`, topology, tuning hardware and checks,
  setup, launchpad, bench devices, flags) and has no Hugging Face success (no network): after N6 and N8, check those
  screens (System, Topology, Tuning, first run, Hugging Face search) in the running app.
- (N6) Hono's `c.json()` sends `application/json` without a charset; the golden (Bun's `Response.json`) has
  `application/json;charset=utf-8`. `jsonCharset` (`server/http.ts`) rewrites exactly that value, so a route that sets
  its own type (profile export: `application/json; charset=utf-8`) keeps it. Node's `Response.json` also omits the
  charset: N8 relies on the same middleware for `errorResponse` and the guard's replies.
- (N6) `@hono/zod-validator` (`body()`) only parses a media type matching Hono's JSON regex
  (`^application/([\w.-]+\+)?json$`); the guard admits anything matching `^application/json\b`. Divergence, no golden
  case: a `body()` route answers `Invalid JSON` to a JSON body sent as `application/json-seq` (or another
  `application/json<non-word>…` type) where it used to parse it. The `json(check)` routes (object or imperative checks,
  lookup-first bodies) still read the body whatever the media type, as before.
- (N6) Hono routes on the decoded path (`c.req.path`), Bun's router matched the raw one. Divergence, no golden case:
  a percent-encoded static segment now reaches the static route (`GET /api/profiles/%69mport` is a 405 `Allow: POST`
  instead of `Profile not found`; a `POST` to it runs the import). The guard still runs first; no client sends these.
- (N6) Order kept from before the port: a body validator runs after `id()` (404 beats 400) but before the handler.
  Where the handler looked something up or answered a 409 before reading the body (PUT `/api/profiles/:id`: the repo
  looks the profile up before parsing; sweeps `resume` and `validate`), the body is passed through (`passthrough`) or
  read in the handler, so an unknown id with a bad body is still 404.
- (N7) `AppType` from `server/api.ts` leaked Node's types into the web: its declaration imported `AppDeps` (→ `bun`,
  `node:*` through every service) and `Env` named Bun's `Server`; the N0(c) per-domain fallback leaks the same way.
  Fixed types-only: `Env.Bindings.server` typed structurally, and `server/rpc.ts` exports the inferred type of a
  never-called `createApi(undefined as never)`, whose declaration imports nothing of the app. Cold `tsc -b` 1.25 s
  (0.81 s before), no-change 0.03 s.
- (N7) Hono's validator types a json/query input as the validator's return type: `json(check)` types the client's
  body by `check`'s return (`POST /api/chat`'s check had to return `{ profileId?: number | null }`), and `json(object)`
  / `json(passthrough)` take any object, so a misspelled key compiles. A route that reads its body after a 409 needs a
  type-only declaration (`accepts<T>()`): any json validator parses first and would turn the 409 into a 400.
- (N7) A route answering `Response.json(…)` (`/api/server/props`) has an untyped reply; the web narrows it with
  guards (`web/src/lib/props.ts`). `hc` sends no body without `json`: the `'{}'` bodies of retry, clear, to-profile,
  stop and regenerate are gone (the guard passes a body-less write, checked in the app).
- (N8) chokidar (under Vite's watcher) throttles `change` per file on the leading edge for 50 ms with no trailing
  event: a second write within 50 ms (format on save, two quick `sed -i`) was lost and the dev reload kept the first
  content (6/6 in a repro). `server/dev.ts` re-stats each changed file 60 ms later (`ino:mtimeNs:size`) and replays a
  dropped change. Vite also watches files outside `root` one by one and loses such a watch after two atomic replaces:
  `server/` and `packages/` are watched as directories.
- (N8) A module-level `WeakMap` in `server/host.ts` was lost when the module runner re-evaluated it: the second mount
  attached a second `upgrade` listener ("handleUpgrade() was called more than once", dev process crash). The
  listeners now live on the server object under `Symbol.for('llama-webui.host.mounted')`.
- (N8) `dist/server/main.js` resolves `hono`, `@hono/node-server` and `ws` from the repo root: under pnpm they must be
  root `dependencies` (not only `server/`'s). The server is bundled into one file (`codeSplitting: false`): with
  chunks, `index.ts` went to `dist/server/assets/` and `../web/` pointed nowhere (503 in production).
- (N8) Bun loaded `.env` from the working directory for `bun run dev`/`start`; Node does not. `server/env.ts`
  (`parseEnv` of `node:util`) is called by both entry points; the environment wins as under Bun, and on the user's
  call `--env-override` or `LLAMA_WEBUI_ENV_OVERRIDE=1` (environment or file) lets the file replace it; `--env-file-if-exists` would print ".env not found" on every start. Bun's `.env.local`/`.env.<NODE_ENV>` are not loaded (never used here).
- (N8) The bundled NVML monitor keeps `new URL('./worker.ts', import.meta.url)`: no such file next to `main.js`, and
  `Worker` is not global on Node, so NVIDIA monitoring falls back to nvidia-smi until N9.
- (N9) Rolldown refuses a second input when `output.codeSplitting` is `false` (`INVALID_OPTION … multiple inputs are
  not supported`): the NVML worker gets its own Vite environment (`nvml`, build only, after `ssr`, `emptyOutDir:
  false`) → `dist/server/nvml-worker.js` (9.6 kB, Node built-ins only). Vite leaves
  `new URL('./worker.ts', import.meta.url)` untouched in the ssr bundle: `workerUrl()` picks the file by the module's
  extension. The typed `dlopen()` of `@types/node` 26.6 types `functions` from the definitions, so `openNvml()`
  returns them as `NvmlSymbols` without a cast. Measured on this machine (2 NVIDIA + 2 AMD): `nvidiaSource: nvml`
  with PCIe rx/tx in dev and prod, `LLAMA_WEBUI_NVML_LIB=/nonexistent` → `nvidia-smi`, SIGINT exit in 50 ms, no
  ExperimentalWarning. A `dlopen` in the test process itself prints the warning: the real-NVML test checks
  `/proc/driver/nvidia/version` instead. `requirements.mdx` still describes Bun: its experimental-FFI note waits for
  its Node rewrite (N12). The final review found that a worker thread stuck in a native call holds the process's
  exit (Node waits for every thread; `unref()` and `terminate()` do not help): measured with libc `sleep(4)` through
  `node:ffi`, `process.exit()` at 210 ms, process gone at 4 027 ms; Bun exits at 230 ms. A driver fault would make
  Ctrl-C hang with port 7860 bound. The sampler therefore runs in a child process (`fork`, IPC, `SIGKILL` on stop,
  exit on `disconnect`): 116 MiB RSS of its own instead of ~67 MiB inside the server's.
- N10: the site's scripts port with no behaviour change: `fs.globSync('**/index.html', { cwd })` lists the same 61
  pages as `Bun.Glob` (root `index.html` included, no warning), and `site/dist/` built by Node is byte-identical to
  Bun's (308 files, sha256). `serve.ts` needs its own MIME table (Node has no type lookup), copied from the types Bun
  reported for the site's files; Bun's `content-disposition: filename=…` on binary files is not kept (Pages does not
  send it). `pnpm <script> --flag` passes the flag through, so `pnpm site:preview --port 4175` works from the root.
