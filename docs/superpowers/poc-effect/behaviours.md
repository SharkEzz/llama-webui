# Behaviours of the Nitro server

The checklist of E0: what each milestone of the Effect rewrite (E1 to E8) brings back, read from the Nitro server as it
stands at commit 6327201a3 (`app/server/`, `app/bin/`, `app/build/` and `packages/`). Each later plan copies its
acceptance list from its section. Every item names the file it was read from; "Not covered by a test" lists what no
entry of `test-inventory.json` exercises.

## E1: Foundation

Closed by E1 (commits up to `chore(poc): Close E1`). Each line is ticked with what proves it (a test, the contract
record `app/server/contract/golden.json`, or a run of the build), struck with `dropped: <reason>`, or moved to its
milestone. A line that changed with the Effect server says how it behaves now.

### Background work

- [ ] The download queue processes one item at a time in a loop started by `enqueue`, `retry` and `resume` (and started again when work was added while it ran, unless disposed), always picking an item left `downloading` first then the oldest `queued` one; `enqueue` and `retry` are serialized so their already-queued and disk space checks see each other's rows (`app/server/lib/hf/downloader.ts`, `app/server/lib/db/downloads.ts`).
- [ ] Each file is fetched with `downloadFetch` (`node:https`, HTTP/1.1, Node's global agents so the environment's proxy applies) from `<endpoint>/<repo>/resolve/<sha>/<path segments URL-encoded>` with `user-agent: llama-webui`, following up to 6 redirects by hand and sending the token only to the Hugging Face endpoint's origin, never to the CDN; more redirects fail the item with 502 `Too many redirects from Hugging Face` (code `hf-unreachable`) (`app/server/lib/hf/downloader.ts`, `app/server/lib/llamaFetch.ts`, `app/server/lib/hf/client.ts`).
- [ ] Each file is written to `<dest>.part` and resumed with `Range: bytes=<offset>-`: a 206 whose `content-range` does not start at the offset deletes the `.part` and retries, a 200 to a ranged request rewrites the file from the start (hash reset), a 416 deletes the `.part` and retries from zero, a `.part` larger than the file is deleted before the request, and a file already in place with the right size is skipped (`app/server/lib/hf/downloader.ts`, `app/server/lib/hf/paths.ts`).
- [ ] Files with an LFS sha256 are hashed as they are written; the hash state is kept across attempts when it covers exactly the `.part`, else the `.part` is re-read from disk in 1 MiB chunks (phase `verifying`); on a size match the digest is compared and a mismatch deletes the `.part` and fails the item with 422 `Checksum mismatch for <path>: the file was deleted` (code `checksum-mismatch`), else the `.part` is renamed into place and the file marked done in the row (`bytesDone` = sizes of finished files) (`app/server/lib/hf/downloader.ts`, `app/server/lib/db/downloads.ts`, `app/server/lib/proc.ts`).
- [ ] Each attempt has a stall timer of 60 s reset on every chunk (`setTimeout`): no data for 60 s aborts the attempt as retryable `no data for 60 s` (`app/server/lib/hf/downloader.ts`).
- [ ] Transient failures (network error `Hugging Face unreachable: …`, status 408, 429 or 5xx from the Hub or the CDN, stall, body shorter than the file which keeps the `.part`, body longer which deletes it, empty body, bad range, 416, any write error other than ENOSPC) are retried after abortable pauses of 2, 4, 8, 16 then 30 s (logged `[llama-webui] download <repo>/<file>: <message>, retrying`), the count reset after an attempt that received data; once spent the item fails with 502 and the last message (code `hf-unreachable`) (`app/server/lib/hf/downloader.ts`).
- [ ] Non-transient failures end the item at once as `error` with message and code: Hub errors (`hf-gated`, `hf-not-found`, `hf-unauthorized`), ENOSPC as 507 `Disk full` (code `disk-full`), checksum mismatch, and any other error as its message with code `download-failed`, logged `[llama-webui] download <repo>/<key> failed: <message>` (`app/server/lib/hf/downloader.ts`).
- [ ] Canceling the running item aborts its request; the queue then deletes its `.part` files, the files it had put in place (or with the right size), and the folders left empty deepest first (shard subfolders, the repo folder, the org folder), then marks it `canceled` (`app/server/lib/hf/downloader.ts`).
- [ ] The disk space check (`enqueue`, `retry`) takes the free space (`statfs`, `bavail × bsize`) of the destination folder or its nearest existing parent and refuses when it is below the bytes still to write (sizes minus existing `.part` bytes) plus what the active items still have to write plus a 1 GiB margin; an unknown free space skips the check (`app/server/lib/hf/downloader.ts`).
- [ ] An unexpected error escaping the queue loop (the database failing) is logged `[llama-webui] download queue stopped:` and the item is picked up again on the next start of the loop (`app/server/lib/hf/downloader.ts`).
- [ ] Hub API calls (search, repo files, whoami) use Node's `fetch` with a 10 s `AbortSignal.timeout`, combined with the client request's signal for search and repo; a 200 that is not JSON is a 502 `Hugging Face sent an invalid response (<path>)`, or `Hugging Face unreachable: …` when the client aborted (`app/server/lib/hf/client.ts`).
- [ ] The model scan walks the models folder recursively (names starting with `.` skipped, directory symlinks not followed, a `.gguf` symlink kept when it points to a regular file, unreadable folders skipped), groups `-0000k-of-0000N.gguf` shards (an incomplete set is an `ok: false` entry `missing shard: <names>`), reads all GGUFs in parallel, reuses a `model_cache` row when the stamp (`mtimeMs:size` of every part) is unchanged, caches each successful read (failures never cached), and deletes the cache rows of files no longer found (`app/server/lib/models/scan.ts`, `app/server/lib/db/modelCache.ts`).
- [ ] `readModel` keeps the last 8 parsed GGUFs in memory keyed by path and the stamp of every part (a changed shard re-reads it), using `@huggingface/gguf` with parameter count (`app/server/lib/models/gguf.ts`).
- [ ] From E3: `downloadFetch` (`app/server-legacy/lib/llamaFetch.ts`, kept until E6): `node:https`, HTTP/1.1 (the HTTP/2 window of Hugging Face caps a stream at ~22 MiB/s), Node's global agents so the proxy of the environment applies, a redirect being the response with its `location` (the downloader follows it); its four tests in `llamaFetch.test.ts` are E6's in the inventory, with the two `fileRange` tests of `lib/proc.test.ts`. ## E8: Tuning and setup

### Endpoints

- [ ] `GET /api/tuning/checks`: reads the optional query key `model` (first value, an empty value counts as absent), then in parallel the tuning hardware, the parsed GGUF of `model` (any `loadModel` failure silently gives `null`, never an error) and the system readings (`readSys`, binary = the `binary` setting with `~` expanded, the in-memory llama-server log lines from `runtime.logs.since(0)`, the monitor's NVML driver info and the bus ids of the monitor's `allGpus`), runs the checks against the latest estimate and disk measurement memoized for that model, and returns `{ checks, summary: { warn, ok, unknown, na }, at }` (`at` = `Date.now()`); errors: none (`app/server/routes/api/tuning/checks.get.ts`, `app/server/lib/tuning/checks.ts`, `app/server/lib/tuning/models.ts`).
- [ ] `GET /api/tuning/hardware`: returns the tuning hardware `{ devices, devicesError, cpu, ramTotalBytes, ramAvailableBytes }`: the `llama-bench --list-devices` devices with their live memory from the monitor, the reason the list is not trusted (or `null`), the CPU info, and RAM from the latest monitor snapshot (otherwise `/proc/meminfo`, otherwise 0); errors: none (`app/server/routes/api/tuning/hardware.get.ts`, `app/server/lib/tuning/memo.ts`, `app/server/lib/tuning/hardware.ts`).
- [ ] `POST /api/tuning/disk-speed`: body `{ modelPath }` (strict object, non-empty string), refuses while the bench runner is busy, validates the model with `loadModel`, then times a sequential read of up to 1 GiB of the file from a random offset and returns `{ bytesPerSec, sampledBytes, path, at }`, which it also memoizes per `modelPath` for the checks; errors: 400 `Invalid JSON`, 400 `JSON object expected`, 400 `Invalid data: …` (body schema), then 409 `A benchmark is running: the measurement would be skewed`, then 400 `Expected an absolute path to a .gguf file`, 404 `Model not found`, 422 `<GGUF read error message>`, then 404 `File not found: <path>` (file gone between the two stats), 400 `File too small to measure (<n> MiB)` (fewer than 64 MiB to read) (`app/server/routes/api/tuning/disk-speed.post.ts`, `app/server/lib/tuning/disk.ts`, `app/server/lib/tuning/models.ts`).
- [ ] `POST /api/tuning/estimate`: body (strict object) `{ modelPath: non-empty string, mmprojPath?: string | null, preset: chat|agent|context|fit|big, pinned?: BenchParams, ctx?: integer 512 to 10,000,000 }`, loads the model, the projector size (0 when `mmprojPath` is missing, null or empty) and the tuning hardware in parallel, runs the rule-based estimator and returns the `Estimate` (`ok`, `reason`, `preset`, `params`, `ctx`, `kv`, `serverArgs`, `rows`, `fit`, `ramOverflowBytes`, `diskReadBytesPerToken`, `warnings`), memoizing it per `modelPath` (also when `ok` is false) for the checks; errors: 400 `Invalid JSON`, 400 `JSON object expected`, 400 `Invalid data: …` (body schema, the preset error being zod's default `Invalid option: expected one of "chat"|"agent"|"context"|"fit"|"big"`), 400 `Expected an absolute path to a .gguf file`, 404 `Model not found`, 422 `<GGUF read error message>`, 404 `Projector not found` (`app/server/routes/api/tuning/estimate.post.ts`, `app/server/lib/tuning/estimate.ts`, `app/server/lib/tuning/models.ts`).
- [ ] `POST /api/tuning/plan`: body `{ spec }` read without a media-type check (`readJson` + `object`), `spec` parsed by `SweepSpecSchema` so its errors keep their own paths (`name`, not `spec.name`), then the model, projector size and tuning hardware loaded in parallel, and returns `{ items: [{ params, label, fit }], excluded, droppedTs, estimatedSeconds }` without storing anything; errors: 400 `Invalid JSON` (empty or malformed body), 400 `JSON object expected`, 400 `Invalid data: …` (spec schema; a body without `spec` gives a message with no path), 400 `Expected an absolute path to a .gguf file`, 404 `Model not found`, 422 `<GGUF read error message>`, 404 `Projector not found` (`app/server/routes/api/tuning/plan.post.ts`, `app/server/lib/tuning/space.ts`, `packages/webui-shared/src/sweep.ts`).
- [ ] `GET /api/setup`: returns the first-run report `{ binary: { setting, path, version }, bench: { path, devices }, models: { setting, dir, exists, count, bytes }, telemetry: { nvidiaSource, perfParanoid }, listen: { host, exposed }, llamaListen: { host, exposed }, ready }`, with `ready` true when the binary is found and the models folder exists; errors: none (`app/server/routes/api/setup.get.ts`, `app/server/lib/setup.ts`).
- [ ] Model loading for estimate, plan and disk-speed (`loadModel`): a path that does not start with `/` or end with `.gguf` is 400 `Expected an absolute path to a .gguf file`, a path that is not a regular file is 404 `Model not found`, and a `readModel` failure (unreadable GGUF, missing shard, permission denied) is 422 with the `ModelReadError` message; the parsed GGUF comes from `readModel`'s cache (8 models, keyed by the size and mtime of every shard) (`app/server/lib/tuning/models.ts`, `app/server/lib/models/gguf.ts`).
- [ ] Projector size (`mmprojBytes`): 0 without a path, the file size of a regular file, otherwise 404 `Projector not found`; the projector path is not checked for being absolute or `.gguf` (`app/server/lib/tuning/models.ts`).
- [ ] Plan body schema (`SweepSpecSchema`): `name` trimmed 1 to 80 characters (`required`, `80 characters at most`), `modelPath` absolute (`expected an absolute path`) and `.gguf` (`expected a .gguf file`), `mmprojPath` string or null (default null), `profileId` integer or null (default null), `p` 1 to 32768 (default 512), `n` 1 to 4096 (default 128), `r` 1 to 20 (default 3), `preset` (`unknown preset`), `base` BenchParams (default `{}`), `space` with each dimension a non-empty list (`at least one value`, default `{}`), `serverArgs` refusing reserved flags and flags covered by a field (`<flag>: use the <short> field`), `includeUnfit` (default false) (`packages/webui-shared/src/sweep.ts`, `packages/webui-shared/src/bench.ts`).
- [ ] `BenchParams` (estimate `pinned`, plan `base`): strict object of `ngl` (0 to 9999, `all` or `auto`), `ot` (`pattern=buffer` strings), `ncmoe` (0 to 9999), `dev` (device names like `CUDA0`), `ts` (non-negative numbers), `sm` (none, layer, row, tensor), `fa` (on, off, auto), `ctk`/`ctv` (f32, f16, bf16, f8_e4m3, q8_0, q4_0, q4_1, iq4_nl, q5_0, q5_1), `t` (1 to 1024), `b` and `ub` (1 to 1,000,000), each with its own message (`packages/webui-shared/src/bench.ts`).
- [ ] Plan items: the cartesian product of `space` over `base` (`expandSpace`, duplicates removed, `-ts` dropped where `-dev` does not have as many devices, counted in `droppedTs`), each with `itemLabel` and its `fitOf` verdict at the sweep context (`-c` from `serverArgs`, else the preset's `ctxMin`), K cache `ctk ?? f16`, V cache `ctv ?? ctk ?? f16`, micro-batch `ub ?? 512`; items whose verdict is `no` are dropped and counted in `excluded` unless `includeUnfit`; `estimatedSeconds` = round(items × (model file bytes / 1.5 GiB/s + 10 s × `r`)) (`app/server/lib/tuning/space.ts`, `packages/webui-shared/src/sweep.ts`).
- [ ] Presets: `chat` (target 32768, min 8192, f16 KV preferred, ub 512), `agent` (65536, 16384, q8_0, ub 2048), `context` (largest that fits, min 8192, q8_0, ub 512), `fit` (8192, 8192, q8_0, ub 512), `big` (32768, 8192, q8_0, ub 512, experts in RAM across all cards, RAM overflow accepted) (`packages/webui-shared/src/tuning.ts`).
- [ ] Estimator card sets: dedicated GPUs (`deviceRole` = `gpu`: no host, iGPU or Vulkan duplicate of a native card) whose budget is at least 256 MiB, CUDA first in `--list-devices` order; a pinned `-dev` gives only that set, otherwise each CUDA card alone, all CUDA cards, each card alone, then all cards (`app/server/lib/tuning/estimate.ts`, `packages/webui-shared/src/tuning.ts`).
- [ ] Estimator families: outside `big`, every card set all-GPU (`-ngl all`), then for a MoE `-ncmoe` 1 to L on the widest set (or the pinned `ncmoe`), then partial `-ngl` L−1 down to 1 on the widest set (or the pinned `ngl`), then CPU only (`-ngl 0 -dev none`); `big` tries only `-ncmoe` (MoE) and partial on the widest set, then CPU; a candidate is rejected when its verdict is `no` or its RAM exceeds the available RAM (except with `big`) (`app/server/lib/tuning/estimate.ts`).
- [ ] Estimator cache and batch: with pinned `-fa off` the KV candidates are f16 then f8_e4m3 (f16 only when both `ctk` and `ctv` are pinned), with a pinned `ctk` f16 or q8_0, otherwise the preset's preferred type (f16 then q8_0, or q8_0 alone); f8_e4m3 is tried only on sets made of CUDA cards; the micro-batches are the pinned `ub`, otherwise `[512]` or `[preset ub, 512]`; every candidate also carries `-fa on` (unless `-fa off` is pinned), `-ctk`/`-ctv` = the KV type, `-t` = pinned or the physical core count (at least 1), `-b` = pinned or 2048, and the pinned values override the searched ones (`app/server/lib/tuning/estimate.ts`).
- [ ] Estimator context search: the maximum context is max(preset min, model context length rounded down to 1024); for the `context` preset without a pinned `ctx`, each KV type gets the largest context (binary search in 1024 steps) over every GPU family then the other families in order, stopping after the first non-GPU family once any family has fitted, and a fallback KV type wins only with a larger context; otherwise the GPU families are tried first at the target context (min(target, max) or the pinned `ctx`) with the preferred KV, the first `fits` wins, else the first `tight`, else every family × KV type × context (target, then down by 4096 to the preset min) × micro-batch, first that passes (`app/server/lib/tuning/estimate.ts`).
- [ ] Estimator `-ts`: on two cards or more, proportional to each card's budget minus the compute buffers and projector on the first card, in 256 MiB units (at least 1); absent on a single card (`app/server/lib/tuning/estimate.ts`).
- [ ] Estimate when nothing fits: `ok: false`, the simplest configuration (`-ngl all` on the widest set, or `-ngl 0` without cards; q8_0 KV, f16 with `-fa off`; ub 512; context = pinned `ctx` or preset min; pinned values applied last), `reason` = `not enough RAM: <X> needed with weights in RAM, <Y> available` when some candidate fitted the VRAM but not the RAM, else the fit's reason, else `model too large: <X> of RAM needed, <Y> available`, `fit.verdict` forced to `no`, empty `rows`, `diskReadBytesPerToken` 0, `serverArgs` ending with `-c <ctx> --fit off` (`app/server/lib/tuning/estimate.ts`).
- [ ] Estimate when a configuration is found: `serverArgs` = the params as llama-server flags, then `-c <ctx> --fit off`, then `--mlock` when the layers are not all on GPU, some weights are in RAM, RAM does not overflow, at least 2 GiB of RAM stays free and there is no `-ncmoe`, then `--numa distribute` when the CPU has several NUMA nodes; `kv` = the final K cache type (pinned included); `ramOverflowBytes` = RAM needed minus available (at least 0); `diskReadBytesPerToken` = active CPU weights (MoE experts × used/total experts, plus other layer weights) × min(1, overflow / CPU weights) when RAM overflows (`app/server/lib/tuning/estimate.ts`).
- [ ] Estimate rows (`{ flag, value, why }`), in order: `-ncmoe` (with `-ngl all`), `-ngl` (`all`, a layer count, or `0`), `-dev` (unless `none`), `-ts`, `-c` (total estimated bytes, KV label), `-fa` (why depends on quantized KV, `auto` or `off`), `-ctk / -ctv` (`pinned`, `cache halved, negligible loss`, `cache halved, works without flash attention` for f8_e4m3, or `the budget allows it, no loss`), `-t`, `-b / -ub` (`default` only for 2048/512), `--fit off`, then `--mlock` and `--numa distribute` when they apply; f32, f16, bf16 and f8_e4m3 are not counted as quantized (`app/server/lib/tuning/estimate.ts`).
- [ ] Estimate warnings: `dense model: -ncmoe has no effect` (pinned `ncmoe` on a dense model), `slow generation: <n> of <L> layers in RAM`, `<experts of the first N layers> in RAM: slower generation`, `not enough VRAM: everything in RAM`, `overflows RAM by <X>: NVMe read ≈ <Y> per generated token`, the `tight` reason when RAM does not overflow, `a quantized KV cache needs flash attention: -fa off may fail`, `only CUDA and the CPU support an f8_e4m3 KV cache: <devices> may fail`, then every placement issue (`app/server/lib/tuning/estimate.ts`).
- [ ] Placement (`measurePlacement`): the used devices are the pinned `-dev` ids that are listed and not host (`none` ignored, any other unknown id an `unknown device: <id>` issue), otherwise the dedicated GPUs; `-ngl` as a number, else every layer plus the output (0 without a device); the last `ngl` layers go to GPU in contiguous slices proportional to `-ts` (when its length matches and one value is positive) or to each card's free MiB (else total), all on the first card with `-sm none` or a single card (`app/server/lib/tuning/placement.ts`).
- [ ] Placement of each tensor: the first matching `-ot` rule wins (a listed device, or RAM for a host buffer like `CPU`, `CPU_REPACK`, `CUDA_Host`; an unknown target is counted in RAM with the issue `unknown device: <target> (-ot <rule>)`; an invalid regex is the issue `invalid -ot pattern: <pattern>`), then experts of layers below `-ncmoe` go to RAM, `token_embd` to RAM, a layer tensor to its layer's device, other tensors to the last device when the output is offloaded, otherwise RAM; KV of each layer goes with its layer; compute buffers (ub × (embedding × 4 + vocab × 4) + 256 MiB), the projector and the recurrent state go to the first device when a layer is on GPU, otherwise RAM (`app/server/lib/tuning/placement.ts`, `app/server/lib/tuning/memory.ts`).
- [ ] KV cache size: no KV for MTP (nextn) layers, for recurrent layers without a full-attention interval, and for layers off the full-attention interval; sliding-window layers (all but every `swaPattern`-th, pattern from the GGUF, 2 for gpt-oss, 6 otherwise) hold at most `slidingWindow` tokens; bytes = KV heads × (key length × K bytes + value length × V bytes) × tokens, with per-element bytes f32 4, f16/bf16 2, q8_0 1.0625, f8_e4m3 1, q5_1 0.75, q5_0 0.6875, q4_1 0.625, q4_0/iq4_nl 0.5625 (`app/server/lib/tuning/memory.ts`).
- [ ] Fit verdict (`fitOf`): the budget of a device is total − (512 MiB + 4 % of total) − VRAM of other processes (at least 0); `no` with an `unknown device` issue as reason, `no` when a device exceeds its budget (`<dev>: <X> for <Y> usable`), `tight` when RAM needed exceeds RAM available (`RAM: <X> for <Y> available, the rest is re-read from disk`), `tight` above 95 % of a budget (`<dev>: <X> for <Y> usable, thin margin`), otherwise `fits` with a null reason; each `vram` entry carries `device`, `bytes`, `budget`, `totalBytes`, `otherBytes` (`app/server/lib/tuning/placement.ts`, `app/server/lib/tuning/memory.ts`).
- [ ] Live memory of the devices (`withLiveMemory`): each `--list-devices` device matched to a monitored card gets `freeMib` = clamp(card total − used, 0, device total) and `otherUsedMib` = device total − live free − the managed llama-server's own VRAM (at least 0), both rounded; unmatched, suspended or zero-VRAM cards keep the list's values (`app/server/lib/tuning/match.ts`).
- [ ] Card matching (`matchGpus`): hidden cards are left out, cards are taken in bus order, one card per device of a backend (a CUDA device and its Vulkan copy may share one), vendor from the backend (CUDA, ROCm/HIP) or the name, NVIDIA matched by name (Vulkan driver suffixes `(RADV …)`, `(AMDVLK …)`, `(NVK …)`, `(ANV …)` stripped), AMD by VRAM total within 2 %; devices with no memory or no vendor are not matched (`app/server/lib/tuning/match.ts`).
- [ ] Retained cards for the checks (`retainedBusIds`): the bus ids of the cards matched to the latest estimate's `-dev` (minus `none`), or to every dedicated card without `-dev`; with an empty device list, every monitored card (`app/server/lib/tuning/match.ts`).
- [ ] Checks order and scope: NVIDIA checks only when the monitor lists an NVIDIA card (per card: persistence, power limit, PCIe, Resizable BAR; then driver and `nvidia_uvm`), AMD checks only when it lists an AMD card (per card: DPM, PCIe; then HIP backend and ROCm recognition), then CPU (governor, THP, memlock, swappiness, NUMA), build (CUDA, SIMD, age) and kernel (IOMMU, model disk, disk bandwidth, swap) checks; a card that is not retained is `na` with `not applicable (card ignored)` for persistence, power limit, DPM, and HIP/ROCm when no AMD card is retained, while its PCIe and BAR checks still run; "the model spills" means the latest estimate is `ok` with `-ngl` not `all` or a `-ncmoe` (`app/server/lib/tuning/checks.ts`).
- [ ] Check `nvidia.persistence.<busId>`: `unknown` (`not reported by NVML`), `ok` (`enabled`), or `warn` (`disabled`, command `sudo nvidia-smi -i <uuid> -pm 1`, the UUID taken from the card key `nvidia:<uuid>`, else the bus id; persistence `session`) (`app/server/lib/tuning/checks.ts`).
- [ ] Check `nvidia.powerlimit.<busId>`: `unknown` (`unknown limit`), `warn` when the limit is more than 1 W under the default (`<n> W, default <d> W`, command `sudo nvidia-smi -i <uuid> -pl <d>`, session), otherwise `ok` (`<n> W (default)`) (`app/server/lib/tuning/checks.ts`).
- [ ] Check `<nvidia|amd>.pcie.<busId>`: `unknown` without a max link (`unknown PCIe link`) or without a current link (`measured under load: start the server first`), `unknown` when below its max while the card is under 10 % use (`x<w> Gen<g> while idle (max …): measured under load`), `warn` when below its max under load (`…: check the slot, riser or BIOS`, permanent), otherwise `ok` (`x<w> Gen<g> (max x<W> Gen<G>)`) (`app/server/lib/tuning/checks.ts`).
- [ ] Check `nvidia.rebar.<busId>`: `unknown` without a BAR size or VRAM total (`unknown BAR1 size`), `warn` when the largest BAR is smaller than the VRAM (`BAR1 <x> < VRAM <y>: enable Resizable BAR / Above 4G decoding in the BIOS`, permanent), otherwise `ok` (`BAR1 <x>`) (`app/server/lib/tuning/checks.ts`).
- [ ] Check `nvidia.driver`: `warn` when the llama-server logs say `driver version is insufficient` (`too old for the build’s CUDA (driver <v>, CUDA <maj>.<min>): update the driver`, permanent), `unknown` without a driver version, otherwise `ok` (`driver <v>, CUDA <maj>.<min>`, the CUDA part only when NVML gave it); check `nvidia.uvm`: `unknown` when `/proc/modules` is unreadable, `ok` (`loaded`), or `warn` (`missing`, command `sudo modprobe nvidia_uvm`, session) (`app/server/lib/tuning/checks.ts`).
- [ ] AMD checks: `amd.dpm.<busId>` is `unknown` (`power_dpm_force_performance_level unreadable`), `warn` on `auto` (command `echo high | sudo tee <file>`, session) or `ok` with the level; `amd.hip` is `unknown` (`build libraries not found`), `ok` (`present`, a `libggml-hip*` next to the binary) or `warn` (`missing: rebuild llama.cpp with -DGGML_HIP=ON, otherwise Vulkan`, permanent); `amd.rocm-gfx` is always `unknown` (`rocminfo not queried: …HSA_OVERRIDE_GFX_VERSION…`) when an AMD card is retained (`app/server/lib/tuning/checks.ts`).
- [ ] CPU checks: `cpu.governor` `unknown` (`cpufreq unreadable`), `ok` when every core is `performance`, else `warn` with the first other governor and the command `echo performance | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor` (session); `cpu.thp` `unknown`, `warn` on `never` (command `echo madvise | sudo tee /sys/kernel/mm/transparent_hugepage/enabled`, session), else `ok` with the mode; `cpu.memlock` `ok` (`--mlock not recommended here`) unless the estimate's args hold `--mlock`, then `unknown`, `warn` under the model size (command `ulimit -l unlimited`, session) or `ok` (`unlimited` or the size) (`app/server/lib/tuning/checks.ts`).
- [ ] CPU checks: `cpu.swappiness` `unknown`, `warn` above 10 while the model spills (command `sudo sysctl vm.swappiness=10`, session), else `ok` with the value; `cpu.numa` `ok` on one node, `ok` when the estimate's args hold `--numa`, else `warn` (`<n> nodes without --numa: add --numa distribute to the profile`, permanent) (`app/server/lib/tuning/checks.ts`).
- [ ] Build checks: `build.cuda` `ok` when a CUDA device is listed or there is no NVIDIA card, `unknown` without backend libraries, `ok` with a `libggml-cuda*`, else `warn` (`missing: rebuild llama.cpp with -DGGML_CUDA=ON`, permanent); `build.simd` `unknown` without a `system_info:` log line (`…start the server first`), `warn` when the CPU has `avx2`/`avx512f` but the line lacks `AVX2 = 1`/`AVX512 = 1` (`…rebuild with -DGGML_NATIVE=ON`, permanent), else `ok`; `build.age` `unknown` without a git checkout, `warn` over 60 days (`<n> days`, command `git pull && cmake --build build`, permanent), else `ok` (`app/server/lib/tuning/checks.ts`).
- [ ] Kernel checks: `kernel.iommu` `unknown` (`/sys/class/iommu unreadable`), `ok` when inactive or in passthrough (`iommu=pt`, `amd_iommu=off`, `intel_iommu=off` on the cmdline), `ok` (`active, single card`) with fewer than two retained cards, else `warn` (permanent); `kernel.disk` `unknown` without a model, `warn` on a spinning disk or a network filesystem (nfs, cifs, smb, fuse, sshfs, 9p, afs, ceph, glusterfs), else `ok` (`<fs>, SSD`); `kernel.disk-speed` `unknown` until measured, `warn` under 2 GiB/s, else `ok`; `kernel.swap` `unknown` without memory info, `warn` when swap is used while the model spills, else `ok` (`app/server/lib/tuning/checks.ts`).
- [ ] System readings (`readSys`), each tolerant (null or empty, never a rejection): governors of `/sys/devices/system/cpu/cpuN`, THP bracketed mode, soft `Max locked memory` of `/proc/self/limits` (`unlimited` = Infinity), `vm.swappiness`, `/proc/cmdline`, `/sys/class/iommu` entries, `/proc/modules`, `libggml-*.so` next to the resolved binary, the last commit date of a git checkout found up to 4 levels above the binary, the driver from NVML else `/sys/module/nvidia/version`, the largest of the first 6 BARs of each monitored card, the DPM level of each `/sys/class/drm/cardN` of a monitored bus id, the last `system_info:` log line, and the model's disk (rotational flag, filesystem of the longest `/proc/mounts` mount point covering it) (`app/server/lib/tuning/sysinfo.ts`).
- [ ] Binary resolution for the checks and the setup (`resolveBinary`): a bare name is looked up in the `PATH` (executable regular files only), a path with a slash is taken as is, a relative one against the working directory, then made symlink-free by `realpath`; `null` when not found (`app/server/lib/tuning/sysinfo.ts`, `app/server/lib/proc.ts`).
- [ ] Setup report details: `binary.path` is the resolved binary only when it is an executable regular file, `binary.version` is `b<build> (<commit>)` from `<binary> --version` (null when unreadable or the binary is not found), `bench.path` is `llama-bench` next to the `~`-expanded binary and `bench.devices` its device list (the last good list or `[]` on failure), `models` counts only readable entries of kind `model` (projectors and unreadable files left out) of `scanModels` on the `~`-expanded `modelsDir` when it is a directory, `telemetry.nvidiaSource` is the monitor's (`nvml` or `nvidia-smi`), `telemetry.perfParanoid` is `/proc/sys/kernel/perf_event_paranoid` parsed (null when unreadable), `listen` is the `--host` llama-webui listens on and `llamaListen` the `host` setting, each `exposed` when not loopback (`^127.`, `::1`, `localhost`, `[::1]`) (`app/server/lib/setup.ts`, `app/server/routes/api/setup.get.ts`, `packages/webui-shared/src/setup.ts`).
- [ ] First-run checklist filter (`isSetupCheck`, shared with the web): drops the checks that need a model or a running server (`cpu.memlock`, `cpu.swappiness`, `kernel.disk`, `kernel.disk-speed`, `kernel.swap`, every `*.pcie.*`, `build.simd`) (`packages/webui-shared/src/tuning.ts`).

### WebSocket messages

None. E8 owns no WebSocket message type (`packages/webui-shared/src/ws.ts`), and its routes broadcast nothing: estimates, plans, checks and disk measurements are only returned to the caller.

### Startup and shutdown

- [ ] E8 registers nothing in `boot()`: the memoized disk measurements and estimates (per model path), the CPU info, the `--list-devices` and `--version` caches and the parsed GGUFs are module-level state in `lib/`, empty at each process start, never persisted and not cleared on stop (`app/server/lib/tuning/memo.ts`, `app/server/lib/tuning/hardware.ts`, `app/server/lib/bench/hardware.ts`, `app/server/lib/boot.ts`).
- [ ] The memos live in `lib/`, not in a route file, so that saving a route file in dev does not reset what `POST /api/tuning/estimate` and `POST /api/tuning/disk-speed` wrote for `GET /api/tuning/checks` (`app/server/lib/tuning/memo.ts`).

### Background work

- [ ] Every tuning-hardware read (`GET /api/tuning/hardware`, `GET /api/tuning/checks`, `POST /api/tuning/estimate`, `POST /api/tuning/plan`) and the setup report spawn `llama-bench --list-devices` (killed with SIGKILL after 15 s), cached per bench binary and modification time; a failed or suspect listing (spawn failure, non-zero exit, signal, a GPU backend device listed with 0 MiB) is not cached and falls back to the last good list of that binary (`[]` if none) with the reason in `devicesError` (`llama-bench --list-devices exited with code <n>`, `… killed by <signal>`, `<id> listed without memory`, or the spawn error), and an empty list is not cached either (no error) (`app/server/lib/bench/hardware.ts`, `app/server/lib/tuning/hardware.ts`).
- [ ] The setup report (`GET /api/setup`) spawns `<binary> --version` (killed with SIGKILL after 5 s) when the binary is found, cached per binary file and modification time (a rebuild is read again), a failure cached as `null` (`app/server/lib/bench/hardware.ts`).
- [ ] Every `GET /api/tuning/checks` whose binary sits in a git checkout spawns `git -C <repo> log -1 --format=%ct` (stderr ignored, no timeout, not cached) for the build date (`app/server/lib/tuning/sysinfo.ts`).
- [ ] The disk measurement (`POST /api/tuning/disk-speed`) reads up to 1 GiB of the model file in 1 MiB chunks inside the request, not tied to the request signal (a disconnected client does not stop it) and not serialized with another measurement; only a running benchmark refuses it (`app/server/lib/tuning/disk.ts`, `app/server/lib/proc.ts`, `app/server/routes/api/tuning/disk-speed.post.ts`).
- [ ] The CPU info of the tuning hardware (`/proc/cpuinfo`, NUMA nodes from `/sys/devices/system/node`) is read once per process and reused (`app/server/lib/tuning/hardware.ts`, `app/server/lib/hardware/cpu.ts`).
- [ ] The setup report (`GET /api/setup`) scans the models folder with `scanModels`, reusing the SQLite `model_cache` table (`app/server/routes/api/setup.get.ts`, `app/server/lib/models/scan.ts`).
- [ ] From E3: The launchpad's logic, `buildLaunchpad()`, lives in `app/server/lib/setup.ts`, an E8 file, and so does its hardware read `readTuningHardware()` (`app/server/lib/tuning/hardware.ts`); it builds one entry per profile, independently and in parallel (a model that cannot be read only sets `modelError`, a failed estimate only drops `fit`); its two tests in `app/server/lib/setup.test.ts` are filed under E8 in the inventory, but E3 owns the route and must keep them green (`app/server/lib/setup.ts`, `app/server/routes/api/launchpad.get.ts`). E3 kept `app/server-legacy/lib/setup.ts` and `routes/api/launchpad.get.ts` for it.
- [ ] From E4: the launchpad (`GET /api/launchpad`) and the tuning hardware (`readTuningHardware`, `withLiveMemory`, `retainedBusIds`) read the monitor's latest snapshot: its `system.mem` (RAM total and available, `/proc/meminfo` without a snapshot) and its `allGpus` (every card, hidden ones included: the live memory of the devices, the retained cards, the fit badge dropped when llama-bench lists no device while the monitor sees GPUs), and `GET /api/tuning/checks` reads its NVML system (`nvml`: the driver and CUDA versions) and the cards of its last snapshot; on the Effect server these are `Monitor.latest` (null before the first tick) and `Monitor.nvmlSystem` (an effect that waits for the collectors), and the CPU info and `/proc/meminfo` parser exist as `readCpuInfo` of `app/server/hardware/cpu.ts` and `parseMeminfo` of `app/server/collectors/system.ts` (`app/server-legacy/lib/tuning/memo.ts`, `app/server-legacy/routes/api/launchpad.get.ts`, `app/server-legacy/routes/api/tuning/checks.get.ts`).
